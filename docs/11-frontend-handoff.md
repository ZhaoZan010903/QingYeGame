## 一、理解项目和当前阶段

原站为 qingyeyouxi.com，采用 SaaS 建站。重建的主要目的是自主掌握网站代码、商品资料、会员、图片及运营配置。首期服务 QQ 炫舞账号的出售与租赁，经营模式为平台自营加代售，客服协助沟通与交付。

不要按“大型在线交易平台”扩展业务。原站出现的充值、交易等入口，不能直接视为可用业务或本期需求。

已经确定的方向：

- 前后端分离，正式前端采用 React，后端采用 Go。
- Redis 和独立图片对象存储已纳入方案，业务数据由本站管理。
- 电脑端和移动端均需适配。本轮 HTML 是首页视觉与交互基准，后续正式开发应拆分 React 组件。
- 核心操作是浏览、搜索、筛选、查看详情、联系客服、收藏，以及会员提交商品后由管理员审核。
- 商品图片取消“200 张总量上限”，不得换成另一个固定总张数上限。单张大小、单批上传数量、并发数和分页大小分别管理。
- 首页需要人工精选、热门推荐和最新上架，不能把“热门推荐”只做成没有行为的标题。

本期不自行增加在线订单、购物车、充值、积分支付、提现、佣金结算、自动租期与续租、回收交易系统或复杂客服工单。此前关于保留积分的早期讨论，已被后续“按实际可用业务简化、先做展示与发布审核”的范围收敛替代。

如果拿到了仓库，先读 `README.md`、`AGENTS.md`、`docs/09-review-items.md`，再读功能、流程、界面及推荐文档。仓库中的“尚未授权开发”“移动端双列”等旧描述可能早于本次确认：经营方已经授权首页开发；当前商品主列表采用手机单列。不要让过期描述阻止已授权工作，也不要默默改写待确认的业务规则。

## 二、以首页 V3 为视觉基准

请直接打开并操作 `frontend/home-preview/index.html`，检查搜索、轮播、推荐切换、筛选和详情抽屉。保留其布局逻辑、字体层级、颜色、留白、细边框和克制的动效，其他页面应像同一个产品。

### 2.1 不改变的视觉方向

| 项目 | 规范 |
| --- | --- |
| 背景 | `#09090B` 黑曜石，避免纯黑大面积平铺 |
| 容器 | `#121215`；悬浮表面 `#18181C` |
| 文字 | 主文字 `#F4F4F6`，次文字 `#8E8E93`，弱化文字 `#52525B`；主要操作和商品信息必须清晰可读 |
| 点缀 | 香槟金 `#D4AF37` 及少量低亮度暖白；不使用青绿、荧光色、紫红霓虹渐变 |
| 主按钮 | 流光白底、深色文字；避免每个按钮都发光 |
| 边框 | 默认 `1px solid rgba(255,255,255,.07)`，悬浮约 `.18`；不加粗描边 |
| 字体 | Inter、系统无衬线、PingFang SC；中文使用适当系统回退 |
| 数字 | 价格、编号、主要数字用 JetBrains Mono，并启用 tabular-nums |
| 标题 | 字重约 500–600，紧凑但可读；移动端断句完整，不留下孤立单字 |
| 图片 | 卡片封面 16:9，圆角约 12px；不使用变形拉伸和复杂促销贴纸 |
| 布局 | 主列表电脑三列、平板两列、手机一列；卡片间距 24px，外侧留白随屏幕调整 |

用户已经要求删除主标题下的那句说明文案，以及今日托管交易额、平均验号耗时、覆盖率等数据面板。后续不得重新加回类似数据墙来填充空间。

### 2.2 动效与交互

- 背景采用可辨识的香槟金弧线、分层柔光和缓慢光束，保留黑曜石层次。用户已要求比初版更明显；主标题使用银白金属光泽，副标题使用香槟金扫光。不可退回几乎看不见的效果，也不做高饱和度霓虹或大面积闪烁。
- 精确鼠标设备可显示平缓跟随的光晕及卡片边缘高光。不要替换系统鼠标，不做拖尾粒子。
- 滚动时以分组淡入、少量位移和轻微背景视差为主。不得劫持滚轮、改变滚动速度或强制吸附整屏。
- 卡片悬浮上移约 2px；主交互使用 `cubic-bezier(.16,1,.3,1)`，卡片过渡约 250ms，入场约 650–700ms，弹层约 300–400ms。
- 手机端不依赖 hover，减少光效开销，保留必要反馈。按钮、搜索和筛选应容易触达。
- 支持 `prefers-reduced-motion`：停用持续背景动画、跟随光和自动轮播，内容仍完整显示。页面隐藏、轮播离开视口、弹层打开时暂停轮播。
- 保留键盘焦点样式、Esc 关闭、弹层焦点约束及关闭后的焦点恢复。轮播的非当前项不能被 Tab 聚焦。
- 不为动效反复读取整页布局；事件适度合并，动画尽量只改变 transform 和 opacity。组件卸载时清除监听、观察器、定时器与动画帧。

## 三、首页与其他页面怎样衔接

首页应依次包括：悬浮导航与搜索、简短主标题、本期甄选轮播、业务快捷入口、热门推荐/最新上架、可筛选商品列表、发布入口与页脚。

| 首页入口 | 后续页面或行为 |
| --- | --- |
| 搜索框、Ctrl/⌘K | 输入商品编号、标题、区服等关键词，进入列表并保留查询条件 |
| 本期甄选 | 运营选定的商品或专题；当前 V3 为三条商品样例，点击进入对应商品 |
| 账号出售 / 账号租赁 | 进入带交易类型的商品列表 |
| 热门推荐 / 最新上架 | 切换对应数据；“查看全部”进入同排序列表 |
| 商品卡片 | 正式站进入商品详情；保留核验报告为详情内的附属信息入口 |
| 发布账号 | 未登录先登录，登录后返回发布页；同时保留联系客服上架 |
| 个人中心 | 登录、我的收藏、我的发布、基本资料等 |
| 客服咨询 | 展示平台客服信息及当前商品编号，支持复制编号 |

轮播要支持前后切换、指示点、暂停/播放、键盘及触屏操作。V3 自动间隔为 7.5 秒，属于可调整的界面参数。用户主动操作后停止自动切换，避免抢走正在阅读的内容；重新播放由用户主动开启。

本期甄选属于人工精选；热门推荐属于规则排序，两者不能混称。首页的精选与推荐结果应去重。V3 下方“浏览全部账号”是独立的完整浏览区，不从完整列表中删除已推荐商品；后续如将它改为独立列表页，保持这一含义。

## 四、后续页面的具体范围

### 4.1 商品列表与详情

列表支持交易类型、价格、区服、性别、XVIP、特色等条件，具体选项按后端配置。支持同组多选；不要把 V3 中用来展示样式的少量单选项当作最终筛选字段。桌面侧栏、移动抽屉共享同一筛选状态；抽屉内修改为草稿，点击应用才生效，取消时不改原结果。

不同计价单位分别比较：出售总价、小时价、日价、周价、月价不能直接混在同一次价格排序中。类型、筛选、排序与分页应保存在 URL，返回列表时恢复位置和条件。筛选为空、接口失败和加载中应有不同界面。

详情展示完整图集、编号、区服、属性、介绍、报价及单位、收藏和客服入口。大图集分页或按需加载，不能只展示前 200 张。已下架商品应说明状态；未公开商品不能通过普通详情接口获得。

### 4.2 登录与个人中心

支持短信注册、短信登录、手机号密码登录、找回密码和退出。短信发送要有真实请求反馈与倒计时；不要用假倒计时冒充发送成功。

游客可浏览、筛选和查看客服信息；收藏与自主发布需要登录。完成登录后返回原操作位置。个人中心包含脱敏资料、我的收藏和我的发布，不放充值钱包或订单结算入口。

### 4.3 自主发布与审核结果

发布流程保持简单：选择出售或租赁 → 填写账号资料和参考报价 → 上传与整理图片 → 保存草稿或提交审核 → 查看结果。

图片支持追加、排序、移除、取消和失败重试；为单批和单文件设可配置约束，不能恢复商品图片总量上限。后续优先按对象存储直传方案接入，上传进度和完成状态必须来自真实请求。

“我的发布”区分草稿、审核中、已展示、退回修改、已下架，显示审核意见。编辑已展示商品后如何复审，遵循确认后的流程；当前不擅自决定保留旧公开版本还是立即隐藏。

商品发布审核状态和账号资料核验状态是两个概念。“审核通过可展示”不自动等于“官方验号通过”，更不等于包赔承诺。

### 4.4 客服与说明页面

默认联系平台客服，按买号、租号、上架等用途展示配置的联系方式。商品咨询附带商品编号，不公开投稿人的私人手机号。没有真实客服配置时展示未配置状态，不生成假的二维码。

关于网站、上架说明、咨询流程、服务协议和隐私说明沿用同一视觉体系；法律及保障文字由经营方提供或确认，不自行编造承诺。

管理后台可以作为后续独立任务。仅分配用户前端页面时，不自动连带建设后台、审核引擎和生产部署。

## 五、热门推荐的接口与边界

首期采用可解释的规则排序，配合人工精选和最新上架；不是协同过滤或用户画像推荐。详细口径见 `docs/10-recommendation-design.md`。

文档中的建议公式为：

```text
热度 = 近7日有效浏览 V × 1 + 近7日有效收藏 F × 5 + 新品分 N
N：首次公开未满72小时为10，否则为0
```

这些权重和刷新周期仍属待确认参数。正式计算由 Go 完成，Redis 加速榜单读取，数据库保留业务记录和可回查结果。前端消费接口返回的有序结果，不自行覆盖服务器排名。

- 候选必须当前公开、内容版本审核通过、分类启用；返回前还要排除已下架商品。
- 有效浏览按访客、商品、北京时间自然日去重；卡片曝光、图片切换和后台预览不等于详情浏览。
- 收藏取消后不再计分，重复收藏不刷新首次收藏时间；图片张数不加分。
- 新品按第一次公开时间计算，编辑或重新上架不重置。
- 热度相同按首次公开时间降序、公开编号升序稳定排序。
- 没有足够行为数据时使用人工精选和新发布补位，并真实标明；不能制造浏览、成交或热度数字。
- 用户选择最新或价格排序时，尊重其选择；条件筛选先于热门排序。

V3 里的热度采用固定虚构数据，只用于演示热门与最新的差别；未接入真实采集、Redis 或推荐服务。请将 mock 数据集中管理，生产接口失败时不能悄悄回退到这份样例。

## 六、前端工程要求

优先沿用仓库已有工程；如果尚未建立前端，可采用 React + TypeScript + Vite。正式工程使用本地构建的样式，不依赖首页预览用的 Tailwind CDN。数据库方案、后端实现和部署方式按项目文档及已确认配置处理，不因前端开发擅自更换。

建议按以下职责拆分组件，而不是把整个 HTML 塞进一个 React 文件：

```text
SiteHeader / SiteFooter / AmbientBackdrop
SearchDialog / EditorialCarousel / QuickAccess
RecommendationSection / AssetCard / AssetGrid
FilterSidebar / FilterDrawer / SortControl / EmptyState
VerificationDrawer / CustomerServiceDialog
AuthForm / PublishForm / ImageUploader / MyListings
```

建议路由：`/`、`/accounts`、`/accounts/:id`、`/login`、`/register`、`/forgot-password`、`/publish`、`/me`、`/me/favorites`、`/me/listings`、`/me/listings/:id/edit`、`/help/:slug`。可按现有路由约定调整，不为更换路径推倒工程。

数据请求集中在 API 层，组件不直接访问数据库或 Redis。交易类型、报价单位、发布状态、核验状态使用明确类型。公开展示的数据不得包含账号密码、身份证件或私密核验材料。服务端负责权限，前端隐藏按钮不能代替鉴权。

商品图片、会员信息和运营配置不再依赖原 SaaS 链接。图片保存对象键及必要元数据，通过自有存储地址加载；在正式页面采用缩略图、按需加载和稳定宽高，避免滚动跳动。

V3 内嵌的图片为生成的概念图，字体和图片已封装进 HTML，生成说明保存在源码注释中。后续应提取为独立资源并替换真实商品素材。不要把概念图当作真实账号截图，不把样例验号证书、信誉星级和包赔标识直接变成生产承诺。相关业务未建立前，应隐藏未支持的认证与保障，或明确显示未提供。

## 七、开发顺序与交付检查

先确认当前指派的页面范围；若要求继续整个前端，按“组件与首页迁移 → 列表/详情/客服 → 登录与收藏 → 发布/我的发布 → 个人中心及说明页”推进。每个阶段保留可运行预览和必要状态，不为等待非关键内容停止所有工作。

交付前至少检查：

- 320、390、768、1440px 宽度下无横向溢出，主列表列数正确，长标题、长编号与不同报价单位不破坏布局。
- 红框删除内容没有重新出现；整体风格与 V3 保持一致。
- 轮播可暂停、前后切换、手势操作；非当前项不可聚焦；进入后台、离开视口或打开弹层时暂停。
- 键盘可以搜索、切换页签、关闭弹层；减少动态效果的用户仍能完整使用页面。
- 推荐顺序和最新顺序不同且可解释；操作“查看全部”后正确带入排序；真实排序不由客户端另算。
- 筛选应用/取消/重置正确；混合报价单位不直接价格排序；返回列表保留状态。
- 图片失败有回退、上传失败可重试，大图集可以继续加载，不恢复 200 张上限。
- 登录前后权限和返回位置正确；未接入接口的功能不得提示真实发送、提交或支付成功。
- 有加载、空结果、错误和失效商品状态；控制台无未处理异常。

只运行与变更相关的必要检查。不要堆叠与实现逐行对应、没有业务价值的测试。交付时说明改了什么、如何启动、检查了哪些关键行为及仍未接入的接口。

GitHub：经营方已经明确授权本版上传，并要求后续代码继续维护已有私有仓库 `QingYeGame`。已授权的任务完成后按仓库约定提交；不另建公开仓库，不改可见性，不强制推送，不上传真实凭据、生产数据或日志。后续生产环境变更仍以明确的部署范围为准。
