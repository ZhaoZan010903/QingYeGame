# 项目概述

## 1 建设背景

现网站采用 SaaS 建站，页面文件虽部署在自有云服务器上，业务接口及图片资源仍依赖第三方平台。现有访问权限不足以直接证明已掌握完整的会员数据库、业务数据和图片资产。网站维护及后续功能调整因此受到原平台能力和数据导出条件的限制。

网站已有商品分类、筛选、详情、登录和客服等页面。根据运营方说明，充值、交易等入口目前无法正常使用。本项目以实际业务和已确认的新需求确定范围，不按 SaaS 模板中的全部菜单重新建设交易平台。

## 2 建设目标

1. 采用 React 和 Go 重写网站，独立管理业务数据及运营配置。
2. 完成商品展示、筛选、详情和客服咨询等基础功能。
3. 增加会员自主上传 QQ 炫舞出售或出租商品的能力，由管理员审核后公开。
4. 增加首页热门推荐，使用本站真实数据计算排序，并保留人工精选。
5. 重新设计电脑端和移动端页面，改善图片展示、筛选和发布体验。

## 3 业务定位

首期网站承担商品展示、信息发布和客服咨询。经营方式为平台自营与代售并存，商品成交由平台客服协助处理。

用户自主发布是新的资料提交渠道。它与联系客服上架同时保留，不同时引入商家店铺、在线收款或自动结算。

商品分为出售与出租两种交易类型。买家导航中的“QQ 炫舞买号”对应出售商品；租赁根据报价单位区分时日租和周月租。当前不建设独立求购信息模块。

## 4 首期范围

| 类别 | 内容 |
| --- | --- |
| 基础功能 | 首页、列表、筛选、详情、注册登录、收藏、客服与说明页面 |
| 新增功能 | 会员投稿审核、我的发布、热门推荐、推荐规则管理 |
| 界面调整 | 电脑端和移动端重新设计，统一卡片、图集、表单和状态提示 |
| 运营管理 | 商品、审核、分类、筛选项、客服二维码、内容、用户及推荐配置 |
| 技术建设 | 自有后端、数据库、Redis、独立图片存储、部署和备份机制 |

以下事项不列入本轮建设：在线订单、充值、积分支付、提现、佣金结算、自动档期、自动续租，以及客服聊天和工单系统。

旧平台若存在会员积分或交易记录，应先核实并归档。停止建设相关前台入口，不等于可以删除历史记录或忽略原有用户权益。

## 5 自主掌控的交付要求

| 资产 | 交付要求 |
| --- | --- |
| 源代码 | React、Go 及构建配置完整提交本私有仓库 |
| 数据库 | 建设方掌握数据、账号、导出、备份和恢复权限 |
| 图片 | 使用建设方自有账号下的对象存储，保留图片清单和迁移能力 |
| Redis | 由建设方控制访问和运行配置，缓存可由数据库记录重建 |
| 域名与部署 | DNS、证书、Nginx 和部署配置可由建设方维护 |
| 短信服务 | 服务账号、模板、费用及密钥由建设方管理，供应商可替换 |
| 管理后台 | 可自行维护商品、审核、筛选、内容、客服和推荐参数 |

云服务器、短信和对象存储可采用成熟服务。自主建设的重点是业务系统、数据和服务账号可控，不要求自行开发这些基础服务。

商品图集不设置固定总张数上限。上传、编辑、展示和审核采用分批处理，文件大小和处理速率单独设置，避免因大量图片一次加载影响使用。

## 6 现状调研依据

调研日期为2026年11月10日，依据包括现站 Nginx 配置、前端文件和公开商品接口样本。

- 业务接口由 Nginx 转发至第三方 SaaS 服务，图片主要引用第三方资源域名。
- 商品接口样本返回量为578，筛选配置返回量为153；不据此认定有效库存或完整历史数据量。
- 个别商品含178张图片，迁移及详情展示需要支持较大图集。
- 收藏及足迹页面源码含模拟数据回退逻辑，新系统应显示真实结果和明确的错误状态。
- 客服验证页面样本主要为图片说明，本轮按内容页处理。

会员实际登录、旧管理后台权限、完整会员数据及资金记录尚未完成核实。数据迁移以原平台实际可提供的导出和授权范围为准。
