# 实施、迁移与验收

## 1 实施顺序

| 阶段 | 工作内容 | 阶段结果 |
| --- | --- | --- |
| 1 需求审阅 | 确认功能模块、业务流程、待定规则 | 更新文档并记录范围版本 |
| 2 界面设计 | 明确视觉方向，设计电脑端与移动端主要页面 | 经审阅的页面设计与交互说明 |
| 3 基础建设 | 数据库、Redis、独立图片存储、后台基础管理及登录 | 可维护的分类、客服、分批图集及测试商品 |
| 4 展示与发布 | 首页、列表、详情、投稿、审核、收藏 | 完整的浏览咨询和投稿审核流程 |
| 5 热门与迁移 | 推荐计算、旧数据导入演练、链接处理 | 可核对的热门结果和迁移报告 |
| 6 验收与上线 | 双端检查、权限与性能验证、备份恢复、切换 | 验收记录、部署版本和运维交接 |

第1阶段文档与 V3 HTML 首页已完成，当前已授权开展 React 用户前端开发。实际完成范围与检查记录见[React 前端实现与接口交接](13-react-frontend.md)。Go 后端、迁移及生产切换仍需分别实施与验收，不能用前端页面完成替代。工期和费用应在范围确认、迁移条件核实后估算，本稿不提供未经评估的工期承诺。

## 2 数据迁移准备

原服务器中的前端文件不等于完整业务数据库。迁移前需要核实原 SaaS 可导出的内容及建设方可使用的数据范围。

| 对象 | 需要核实的内容 | 处理原则 |
| --- | --- | --- |
| 商品 | 编号、分类、标题、属性、报价、状态、发布时间 | 保留旧编号映射；不能确定的字段进入待核对清单 |
| 图片 | 原文件或可下载资源、数量、顺序、访问期限 | 下载并校验后进入自有存储，不继续依赖第三方外链 |
| 分类筛选 | 分组、选项编码、名称、单选或多选 | 建立新旧编码对应表 |
| 客服与内容 | 联系方式、二维码、首页图片、说明页面 | 核对仍有效的内容后重新配置 |
| 会员 | 手机号、旧编号、可导出的认证数据及权限 | 仅在来源和格式明确后导入；不假设旧密码可直接迁移 |
| 历史记录 | 实际存在的积分、交易等记录 | 单独核实及归档，不混入本期商品报价或删除 |
| 旧链接 | 分类和商品详情地址 | 建立映射，已迁移商品跳转至对应新页面 |

现有接口样本不能证明会员库或历史记录完整可得。如无法取得兼容的密码散列，迁移用户通过短信重新验证并设置密码，不复制明文密码。旧积分价格也不得直接按1:1作为人民币价格导入。

## 3 迁移步骤

1. 导出原始资料，保存只读副本及来源说明。
2. 统计商品、分类、图片和会员条数，标记重复、缺失及无效数据。
3. 确认新旧分类和报价单位的对应关系，抽样核对复杂筛选和大图集。
4. 在隔离环境试导入。使用旧编号去重，同一批次重复执行不得产生重复商品。
5. 校验图片数量、顺序、尺寸及完整性。下载失败的文件列入报告，不用占位图冒充迁移成功。
6. 运营核对商品状态和内容。待核对商品先不公开，不因旧站可访问就自动认定已审核。
7. 确定正式导入窗口，记录冻结期间和切换后的新增、修改数据。
8. 正式导入后复核总量、抽样详情、旧链接和客服入口，再开放新站访问。

数据文件、完整会员信息、图片原始包和生产备份不提交 GitHub。仓库只保留迁移工具、字段映射模板和脱敏后的核对报告。

## 4 上线与回退

上线前确认域名、HTTPS、短信、对象存储、数据库、Redis 和管理员账号均可由建设方控制。数据库及实际图片文件完成备份，并核对图片清单后，再切换 Nginx 或域名指向。Redis 可以从业务记录重建，不替代数据库和图片备份。

切换期间应明确旧站何时停止写入，新站何时开始接收注册、发布和收藏。避免两套系统同时写入造成数据无法合并。

出现需要回退的故障时，先停止新系统写入并备份切换后的新增数据，再恢复原入口；不能只恢复旧页面而丢弃新产生的会员和投稿。具体可回退步骤在部署方案中随实际环境补齐。

## 5 验收清单

以下为未来开发的验收要求，当前未执行。待确认规则变更后，应同步修改对应条目。

| 编号 | 项目 | 通过条件 |
| --- | --- | --- |
| A01 | 商品展示 | 首页、列表、详情仅公开已通过当前版本审核且分类启用的商品；猜测编号不能读取待审资料 |
| A02 | 搜索筛选 | 编号、标题、同组多选和跨组筛选正确组合；返回列表保留条件；不同租赁单位不混用价格区间 |
| A03 | 图集 | 顺序与封面正确，列表加载缩略图；大图集分批查看，旧样本178张图片不被静默截断 |
| A04 | 注册登录 | 短信用途、过期、重放和频率限制生效；密码重置后旧会话失效；游客可浏览和咨询 |
| A05 | 投稿 | 草稿可保存和继续编辑；必填项不足不能提交；无法绑定他人私有图片 |
| A06 | 审核 | 退回必须有原因；用户能查看并修改；通过后公开，审核记录保留 |
| A07 | 并发修改 | 管理员打开旧版本后，用户修改资料，旧审批返回冲突，不通过未经审核的新内容 |
| A08 | 编辑及下架 | 按确认后的复审规则处理；撤回和下架立即退出公开查询及推荐候选，不等待热度重算 |
| A09 | 收藏 | 本人数据隔离；重复收藏只有一条；取消后不计分，再次收藏不重置首次收藏时间 |
| A10 | 热门 | 同访客同商品同日只记一次；只计算符合公开条件的商品；数据不足时按新发布补齐 |
| A11 | 推荐管理 | 权重修改后可重算并查看分数构成；人工精选、热门、新发布在同次首页响应中去重 |
| A12 | 客服内容 | 修改二维码后前台更新；缺失配置显示明确说明；待发布内容不公开 |
| A13 | 双端界面 | 1440、768、390、360像素下无整页横向溢出；图片不变形，关键操作可触达 |
| A14 | 权限 | 会员不能访问后台、修改他人商品、指定审核状态或改变精选顺序 |
| A15 | 文件上传 | 文件类型、大小、解码和归属检查有效；私有上传不能被匿名获取；失败可分张重传 |
| A16 | 旧站迁移 | 重复导入不重复建商品；图片数量与顺序可核对；已映射旧链接可到达对应新商品 |
| A17 | SaaS 独立性 | 停止访问旧平台业务接口和资源域名后，仍可完成注册、投稿、审核、展示和收藏 |
| A18 | 备份恢复 | 在隔离环境实际恢复数据库和图片资料，能还原商品、配置、权限及审核记录 |
| A19 | 平台录入 | 管理员可录入并校验发布平台商品，无需人为拆成多人审批；发布版本和操作人可查 |
| A20 | 图集总量 | 分别使用201、500和1000张测试图检查追加、保存、排序、审核和详情；单批处理后可继续，不因总张数被拒绝或截断。这些样本数量不定义新上限 |
| A21 | Redis 故障 | 缓存丢失后可重建；不可用时限流回查数据库或按新发布补位；不得绕过商品公开检查，短信接口不得无限放行 |
| A22 | 排名正确性 | 算例结果、同分次序、7日边界和72小时边界符合规则；旧商品日期未知不加新品分，图片张数不参与热度 |
| A23 | 计算批次 | 新榜单完整写入后切换；空榜单清除旧候选；重复刷新不叠加分数，缓存与数据库回查顺序一致 |
| A24 | 图片存储 | 文件位于建设方自有存储；未审原始图片保持私有；可导出原图、展示图及引用清单，并在隔离环境验证恢复 |

性能验收应先确定测试数据量、图片规模、并发场景和网络条件，再制定响应时间目标。不能仅以本地页面打开正常作为上线依据。
