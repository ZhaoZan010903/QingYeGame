# React 前端原型：配置与工程说明

版本：`0.6.0-prototype.1`，2026年11月11日。

当前 `frontend/web/` 是交互原型，包名为 `qingye-web-prototype`。保留目录是为兼容既有工具及部署。HTML视觉参考在 `frontend/home-preview/`；真实Go服务、管理后台与正式业务前端验收尚未完成。

## 1 职责划分

以下路径相对于 `frontend/web/src/`。

| 位置 | 职责 | 后续修改方式 |
| --- | --- | --- |
| `main.tsx` | 路由、访问门槛、错误边界；除首页外按路由加载 | 新页面注册路由，服务端仍需验证权限 |
| `pages/HomePage.tsx` | 组合首页内容和加载／空／错误状态 | 页面不计算热度或混入样例商品 |
| `components/EditorialCarousel.tsx` | 精选轮播与暂停控制 | 内容与轮播间隔通过属性传入 |
| `components/HomeEntrance.tsx`、`useHomeEntranceMotion.ts` | 开场视图与测量／动画逻辑分开 | 布局变化才重测，滚动只更新局部元素 |
| `components/CatalogSearch.tsx` | 单一搜索输入及归位动画 | 保留输入节点；布局测量与逐帧绘制分离 |
| `components/AmbientBackdrop.tsx` | 背景和阅读进度 | 触屏设备降低持续绘制开销 |
| `lib/home-content.ts` | 类型化展示配置、边界校验、分区去重限量 | 修改默认值，或由真实 `/home.presentation` 提供 |
| `lib/api.ts` | 请求、响应转换、会话与数据模式边界 | 接入真实服务时按接口契约联调，不在组件中直接拼业务响应 |
| `lib/demo-catalog.ts`、`lib/fixtures.ts` | 演示筛选排序与样例库存，动态加载 | 仅演示使用；不能作为API失败兜底 |
| `lib/query.ts` | 与演示库存无关的查询规则 | 修改规则时补查询边界测试 |

仍有历史样式兼容层与较大的接口适配文件。后续应按功能逐步收敛样式及拆分业务服务，并以界面回归和接口契约测试保护行为；本次没有声称已完成所有生产级重构。

## 2 目前哪些内容可修改

原型模式下，首页展示设置集中在 `defaultHomePresentation`，样例商品集中在 `fixtures.ts`。修改代码后需重新构建。API模式下，商品、分类筛选、客服和说明页分别读取对应接口；首页可在 `GET /api/v1/home` 的 `data` 下提供可选 `presentation`：

```json
{
  "presentation": {
    "editorial": { "title": "本期甄选", "description": "每一份热爱，都有独特的模样", "intervalMs": 7500 },
    "sections": [
      { "source": "hot", "title": "热门推荐", "description": "此刻值得关注", "limit": 6 },
      { "source": "newest", "title": "最新上架", "description": "发现新近公开的账号", "limit": 6 }
    ],
    "shortcuts": [
      { "href": "/accounts?trade_type=sale", "title": "账号出售", "description": "浏览出售账号", "icon": "arrow" }
    ],
    "publishing": { "title": "让珍藏，遇见下一位知己。", "description": "提交资料或联系客服", "action": "发布我的资产" }
  }
}
```

这是原型的可选扩展契约，Go服务和后台编辑页尚未实现。正式接入时需要服务端保存、权限、校验、发布状态与缓存更新，不能仅增加前端表单便视为后台已完成。

- 缺字段或类型不符时使用默认值；合法数组中的无效条目会被丢弃。
- `sections` 只接受 `hot`、`newest`，顺序可调，同来源只出现一次；`limit` 为1–24的整数。显式空数组隐藏对应分区。
- `shortcuts` 最多4项，允许 `/accounts`（可带查询）及 `/publish`；外链不接受。显式空数组隐藏快捷入口。
- 轮播间隔接受4000–30000毫秒整数；文案按字段限长，仅作为纯文本渲染。
- 展示保留接口商品次序，按分区顺序去重并限量。真实库存为空时显示空状态，不用样例补足数量。
- 品牌、首页开场标语、核心导航和功能提示仍是界面代码；后续如需运营编辑，应另设明确类型、长度与布局约束。

## 3 手机滚动与加载约定

动效在布局变化时读取尺寸，普通滚动合并到一个待执行动画帧。首页仅更新标题等局部节点的 `transform`、`opacity`，过渡结束后由文档自然滚动；集市搜索使用缓存起止位置，保留唯一输入节点及未提交文字。尺寸变化、减少动态效果和用户操作均须正确处理。

手机上保留金色背景构图，关闭持续SVG流动和部分模糊／缩放特效。商品真实图片保留懒加载及异步解码；其他页面与演示样例按需加载，避免首页一次加载全部页面实现。

验收应覆盖：320／390／768／1440宽度、短屏和横屏、前后滑动、输入法展开、搜索草稿、键盘操作、减少动态效果及浏览器返回。性能对比应使用相同构建模式、视口、CPU限速和滚动轨迹；桌面模拟结果不等同于真实iOS／Android设备帧率保证。

## 4 正式化仍需完成

先实现公开接口与运营配置，再接入身份／短信、会员投稿、图集存储、审核和后台权限；完成真实数据、异常、兼容性及生产迁移验收。原型中的本地登录、收藏、草稿、图片和投稿不能替代这些服务。具体顺序和待定经营规则见[开发进度](14-development-progress.md)。
