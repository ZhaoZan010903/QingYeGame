# 第三轮安全修复与交叉检查

日期：2026-11-11。范围：后端依赖、认证与媒体隔离的回归、独立验收脚本和环境示例。测试使用专用 PostgreSQL/Redis 验收数据，不读写旧生产站，不在记录中保存密码、Cookie 或令牌。

## 第二轮交叉检查的结论

认证与媒体实现者只读检查了另一实现者负责的推荐、公开输出及配置接口。显式商品字段投影不会返回 owner、原始导入载荷及审核内部字段；推荐批次使用同一截止时间和一致性快照，公开结果继续检查商品版本与分类状态。发现的分类交易类型静默不生效、跨管理员保留客服二维码受阻问题，已交原实现者修复并补真实数据库回归，详情见 [第二轮检查记录](../业务验收与审查记录/backend-review-round-2--后端第二轮审查.md)。

主流程独立检查另发现：未知账户的 bcrypt 比较成本为10，而 SeedUser 账户为12。已改为固定有效的 cost12 比较哈希，不在每个未知账户请求中重新生成；单元检查哈希有效性，真实数据库测试实际调用 SeedUser 后核对两者成本一致。此修复避免由两种成本明显不同造成的时序差异，不宣称所有网络时序都恒定。

升级后源码扫描结果：**0个可达漏洞、0个已导入包漏洞**。扫描还报告依赖模块内存在19项当前代码未导入/未调用的漏洞；这不等于整个依赖树完全没有公告。后续增加功能或升级工具链时应重新扫描。

## 验收断言的误报修复

主流程的R2安全验收在“下架收藏不含私有图片和介绍”处失败。原脚本对整个收藏响应搜索通用测试介绍；同一独立验收库保留R1仍公开商品时，其合法介绍也会触发失败。

脚本现按本轮商品ID定位唯一收藏条目，再逐项要求 `status=offline`、`images=[]`、`image_total=0`，以及介绍为空或不存在。不再把其他仍公开的收藏当成当前已下架商品。服务端原有下架占位逻辑没有因此放宽。

新增回归覆盖：同时存在旧的公开收藏与本轮下架收藏时通过；当前条目携带私有介绍、图片、非零图片总量、错误状态，或者当前条目缺失/重复时失败。R3远端完整安全验收结果由主流程重跑后补入最终验收记录，不能用该单元回归冒充远端全流程通过。

## 发布前R4补充：依赖模块与实际精简构建双重核验

主流程在最终发布的 `-ldflags='-s -w'` 精简二进制上得到与上述未精简构建不同的19项 x/crypto 告警。前一次源码和保留符号的构建扫描均未显示这些调用路径可达；精简产物缺少部分符号，二进制分析信息不足，不能将其结果直接描述为新增19条已经证实的可利用路径。本项目直接使用此模块的 bcrypt，传递使用 blowfish，不使用 SSH/OpenPGP。为消除依赖模块中这些已知公告，仍对模块进行了升级，并重新扫描实际交付格式。

截至本轮查询，`go list -m -json golang.org/x/crypto@latest` 与 [Go官方版本列表](https://pkg.go.dev/golang.org/x/crypto?tab=versions)显示最新稳定标签为0.58.0，没有已验证的0.59稳定标签。依照[GO-2026-5932公告](https://pkg.go.dev/vuln/GO-2026-5932)，精确锁定官方修复提交 `v0.58.1-0.20261009181718-2f1f834330b2`，这是提交版本，不将其称为稳定发行版。[对应提交](https://github.com/golang/crypto/commit/2f1f834330b2)把已弃用的OpenPGP拆到独立模块；本项目不依赖该独立模块，并非声称OpenPGP本身已变安全。

`go.mod`、`go.sum`同步更新：x/crypto从0.43.0升级到该精确提交，关联x/text从0.41.0升级至0.43.0、x/sync从0.22.0升级至0.24.0，最低Go版本从1.25升至1.26。实际使用Go1.27.3构建；`go mod verify`验证所有下载模块通过。
