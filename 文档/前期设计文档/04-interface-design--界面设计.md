# 界面设计要求

## 1 设计目标

重新整理电脑端和移动端界面，以商品图片、账号信息和筛选效率为重点。统一导航、卡片、图集、表单、审核状态和客服入口，减少重复内容及无实际业务支持的按钮。

已完成 HTML 首页视觉基准：黑曜石背景、香槟金点缀、银白按钮及金属扫光标题。采用可辨识的柔光、流光弧线和鼠标边缘高光。具体实现见 文档/原型代码/HTML/，后续页面沿用 文档/前期设计文档/11-frontend-handoff--原始视觉设计交接.md。

## 2 页面结构

| 页面 | 主要内容 | 主要操作 |
| --- | --- | --- |
| 首页 | 品牌、搜索、分类、精选、热门、新发布 | 找号、看详情、发布商品 |
| 商品列表 | 搜索、筛选、排序、商品卡片 | 选择条件、查看详情 |
| 商品详情 | 图集、编号、属性、介绍、报价单位 | 收藏、联系平台客服 |
| 注册登录 | 手机号、验证码或密码、协议 | 注册、登录、找回密码 |
| 发布商品 | 交易类型、分类、属性、图片、参考报价 | 保存草稿、提交审核、联系客服上架 |
| 我的发布 | 商品状态、最近审核意见 | 修改、重新提交、撤回、下架 |
| 个人中心 | 基本资料、收藏、发布、最近浏览 | 管理本人资料及记录 |
| 客服与说明 | 二维码、公开账号、服务说明、协议 | 查询联系方式、阅读流程 |
| 管理后台 | 商品、审核、分类、内容、用户、推荐 | 维护与审核 |

## 3 电脑端

### 3.1 首页与列表

首页按人工精选、近期热门和新发布分区。导航突出找号、发布和客服。商品使用一致比例的封面，卡片内明确区分出售价格与租赁单位。

列表提供固定侧栏或顶部筛选区。已选条件可单独移除，也可统一清空。长标题适当截断，价格、类型和关键属性不得因截断而丢失。

### 3.2 详情

图集与商品资料采用双栏布局。图集支持缩略图、按需查看原图和连续浏览；右侧显示编号、属性、参考报价、收藏与客服入口。大量图片分批加载。

### 3.3 发布与审核

发布表单按交易类型、账号资料、图集、报价及介绍分区。保存和提交审核使用不同按钮，并说明当前结果。

审核页同时展示图片、资料、内容版本和提交时间。图集分批获取，显示总数量及当前加载进度，不因图片超过200张截断内容。通过与退回操作应清晰区分，退回时要求填写原因。

## 4 移动端

### 4.1 首页与列表

首页采用紧凑头部、明确搜索入口和单列主列表；热门/新上架区域支持横向卡片浏览。轮播可暂停、手动切换与手势操作。找号、发布和个人中心提供明确入口。

筛选采用抽屉或独立面板，支持清空和确认。关闭筛选面板后回到原列表位置，已选条件仍可查看。

### 4.2 详情

图集和资料纵向排列，主要操作放在底部固定区域。固定区域应预留系统安全区，不遮挡最后一段内容。客服二维码支持长按查看或保存。

### 4.3 发布与我的发布

发布表单采用单列布局，支持从相册选择多张图片并持续追加，显示队列、已完成数量、失败及重试。商品图片不设固定总张数上限；选择较多文件时分批处理，不同时解码所有预览图。资料未提交前退出，应提示保存草稿。

我的发布采用状态标签和纵向列表，审核原因直接展示在对应商品旁，不依赖用户逐层查找。

## 5 组件与状态

| 组件 | 要求 |
| --- | --- |
| 商品卡片 | 封面比例一致，标题、属性、类型、报价单位层级清晰 |
| 筛选控件 | 单选与多选明确，选中反馈不只依赖颜色 |
| 图片上传 | 显示已保存与待上传数量，有进度、重试及排序反馈；单批处理数量不作为商品总量限制 |
| 表单 | 使用可见标签，错误提示对应具体字段，失败后不清空资料 |
| 状态标签 | 明确标识草稿、待审、退回、展示中及下架 |
| 加载与空结果 | 有加载反馈、重试或清除筛选操作，不填充模拟数据 |
| 弹层与抽屉 | 有关闭按钮，支持键盘焦点及返回操作 |

## 6 适配与验收

- 检查宽度至少覆盖1440、768、390和360像素。
- 页面不得出现整体横向溢出；表格等局部区域必要时独立滚动。
- 主要触控区域不小于44像素，正文建议14至16像素。
- 图片保持比例，商品列表不直接加载全部原图。
- 主要表单支持键盘操作，并提供可见焦点。
- 电脑端和手机端使用同一业务数据，分别安排布局，不采用整页等比例缩小。

视觉设计应优先提交首页、列表、详情、发布、我的发布及审核页进行评审。通过后再扩展其他页面。
