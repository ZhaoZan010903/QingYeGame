# R19：聊天界面与图文消息

记录日期：2026年11月12日。

状态：需求已记录，待设计与开发。本记录不代表功能已完成；测试环境已发布版本仍为 R18。

## 1. 本轮目标

改善聊天页面的阅读和输入体验，支持发送图片与文字，并补齐聊天气泡和头像展示。

## 2. 用户明确提出的需求

| 编号 | 需求 | 预期结果 |
| --- | --- | --- |
| R19-01 | 美化聊天界面与聊天框 | 整理聊天区域、输入区域及操作按钮，让对话更清楚、操作更方便 |
| R19-02 | 支持图＋文发送 | 聊天中能够发送图片和文字，让用户与客服直接交流账号资料 |
| R19-03 | 聊天气泡 | 通过气泡样式区分发送方，改善消息层次、间距与长内容阅读体验 |
| R19-04 | 支持头像 | 在聊天中展示参与者头像，便于识别对话对象 |

以上四项为本轮已确认范围。下述交互与技术细节属于后续设计建议，不视为用户逐项确认。

## 3. 建议的界面与操作设计

### 聊天布局

- 用户端延续现有深浅双主题，管理端延续清晰、易操作的工作界面。
- 整理会话列表、对话标题、当前咨询商品、消息区与输入区的层级。
- 兼顾电脑和手机布局；手机键盘弹起、图片加载时，避免遮挡输入框或打断阅读位置。

### 图文消息

- 输入区提供明确的添加图片入口；选图后展示待发送预览，允许移除，再配合文字发送。
- 支持纯文字、纯图片及图片配文字；图文在一条消息中组合还是关联展示，在详细设计时确定。
- 图片在气泡内按比例显示，点击可放大；上传中、发送中、失败与重试的状态应易于理解。
- 单次图片数量、文件大小与允许格式在实现设计中明确，不在本记录中预设数值。

### 气泡与头像

- 本人和对方消息左右区分，保持两种主题下的文字、背景对比度；长文字自动换行。
- 图片、文字与已有商品消息采用协调的视觉样式，避免图片撑破气泡或页面。
- 会话列表与消息区使用一致的头像；没有头像或加载失败时提供默认头像。
- 头像设置入口、上传方式、是否需要裁剪，以及客服使用个人头像还是统一客服头像，留待界面设计时确定。

## 4. 实现时需要保留的能力

- 同步考虑用户端与管理端的收发和展示，保留当前咨询商品入口。
- 保留 WebTransport 优先、同源 WebSocket 兼容，以及已有通知、重连和消息去重机制。
- 保留 R18 会话游标分页、消息历史分页与实时刷新位置处理，避免为展示图片一次拉取完整历史。
- 图文消息的存储结构、接口字段和旧消息兼容方案需随代码说明；不能仅实现本地图片预览。
- 聊天图片读取需校验会话权限；头像的展示权限与聊天附件分别设计，不直接复用商品图片的公开访问规则。

## 5. 后续验收重点

以下为开发后的验收清单，目前尚未执行。

- [ ] 电脑和手机聊天布局清楚，用户端深浅主题及管理端均可正常使用。
- [ ] 用户与管理员双向发送文字、图片及图文内容，刷新后仍能正确查看。
- [ ] 气泡对齐、长文字换行、图片比例与放大预览正常。
- [ ] 有头像、无头像及头像加载失败时均有合理展示。
- [ ] 上传或发送失败有提示，重试不产生重复消息。
- [ ] 未登录、无关会员及失去会话权限的客服不能读取聊天附件。
- [ ] 翻阅历史、实时收到新消息、未读提醒及两种传输方式的现有功能通过回归。
