# TECH-STACK -- 技术栈与扩展边界

此处记录已经存在的实现，不把前期选型建议当成已落地功能。精确版本以每个项目锁文件为准。

| 层 | 当前采用 | 选择与边界 |
| --- | --- | --- |
| 用户前端 | React19、TypeScript5、React Router7、Vite7、Lucide图标 | 独立工程；路由按需加载、API与显式演示模式分离 |
| 管理前端 | 同上，独立package、锁文件、入口与dist | 不从用户工程导入登录状态和管理路由 |
| 前端测试 | Vitest4.1.12，浏览器验收使用Playwright驱动Chrome | 单测、真实接口验收、模拟慢响应分别标记范围 |
| 后端 | Go标准库net/http，最低Go1.26，本轮1.27.3；当前不是Gin/Echo/Fiber | 一个模块，public/admin两个进程；按文件职责拆分 |
| 数据库 | PostgreSQL15、pgx5.9.2连接池 | 商品事实、版本、审核快照、去重与事务锁；每进程最大5连接 |
| Redis | 独立Redis7实例、go-redis9 | Lua原子限流、可重建批次指针；不虚称已缓存全商品列表 |
| 媒体 | 本机受控目录，x/image0.45，720px JPEG派生缩略图 | 保留原字节；访问鉴权、延迟加载和解码并发限制 |
| 登录 | bcrypt成本12、随机会话令牌只存散列、HttpOnly Cookie | 角色/audience/Origin校验，短信供应商未配置 |
| 部署 | Linux、systemd、独立Nginx、静态dist和Go二进制 | API、DB、Redis只监听本机；原型5178独立保留 |
| 工具 | Python标准库迁移、校验、验收及备份脚本 | 原图和私有报告留服务器，源码可审查 |

首页文案、栏目数量与顺序、轮播间隔、精选、分类和筛选、客服、内容页与推荐参数均通过数据库配置。后续扩展不应恢复成仅修改组件内常量。

数据库采用幂等初始化加有序SQL迁移，以事务、互斥锁及schema_migrations记录避免并发重复应用。R5首条数据迁移落实2026年11月11日确认的出售元、时日元/日、周月元/月规则，保留来源且不覆盖人工报价。媒体可替换为对象存储，但须保留媒体ID、顺序、权限和原图内容散列。小服务器上的并发测试只是当前数据和请求组合的证据，未来容量增长需重新测量。

系统图、E-R、审核流程、媒体及热门数据流、当前Redis职责和后续防击穿方案见[架构实体与数据流](17-architecture-and-data-flows--架构实体与数据流.md)。
