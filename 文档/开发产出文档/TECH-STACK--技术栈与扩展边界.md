# TECH-STACK -- 技术栈与扩展边界

此处记录已经存在的源码实现，不把前期选型建议当成已落地功能。精确版本以每个项目锁文件为准；实际部署版本另查发布记录。本轮 Gin 分层决策及安全、性能边界见 [ADR](ADR-GIN-LAYERS--Gin分层与安全性能设计.md)。

| 层 | 当前采用 | 选择与边界 |
| --- | --- | --- |
| 用户前端 | React19、TypeScript5、React Router7、Vite7、Lucide图标 | 独立工程；路由按需加载、API与显式演示模式分离 |
| 管理前端 | 同上，独立package、锁文件、入口与dist | 不从用户工程导入登录状态和管理路由 |
| 前端测试 | Vitest4.1.12，浏览器验收使用Playwright驱动Chrome | 单测、真实接口验收、模拟慢响应分别标记范围 |
| 后端 | Gin1.12.0；最低Go1.26，本轮构建工具链Go1.27.4 | 一个模块，public/admin两个进程；领域、应用、基础设施、传输和启动装配分层 |
| 数据库 | PostgreSQL15、pgx5.9.2连接池 | 商品事实、版本、审核快照、去重与事务锁；每进程默认最多5连接，启动配置可调整 |
| Redis | 独立Redis7实例、go-redis9.12.1 | Lua原子限流、聊天票据/租约/通知及可重建批次指针；没有全商品列表缓存 |
| 媒体 | 本机受控目录，x/image0.45，720px JPEG派生缩略图 | 旧站原图字节保留；新上传校验并重编码；网络接收阶段不占数据库连接，读取先鉴权 |
| 登录 | bcrypt成本12、随机会话令牌只存散列、HttpOnly Cookie | 密码比较每进程2槽；角色/audience/Origin校验；身份只在单次HTTP请求内复用；短信供应商未配置 |
| 实时咨询 | WebTransport优先、同源WebSocket兼容 | 短时单次票据和连接租约；每条命令重新校验会话，消息在PostgreSQL持久化和去重 |
| 部署 | Linux、systemd、独立Nginx、静态dist和Go二进制 | HTTP API、DB、Redis只监听本机；聊天另有受控公网UDP入口；原型5178独立保留 |
| 工具 | Python标准库迁移、校验、验收及备份脚本 | 原图和私有报告留服务器，源码可审查 |

首页文案、栏目数量与顺序、轮播间隔、精选、分类和筛选、客服、内容页与推荐参数均通过数据库配置。后续扩展不应恢复成仅修改组件内常量。

后端目录边界为 `internal/domain`（纯规则）、`application`（用例与端口）、`infrastructure`（PostgreSQL、Redis、文件及密码实现）、`transport/httpapi`（Gin及协议适配）、`config`（部署参数）、`bootstrap`（依赖和生命周期）、`maintenance`（显式维护命令）。应用服务不依赖Gin或SQL；事务型仓储方法保留完整业务锁和提交边界。分层不是微服务拆分。

默认普通API Context预算15秒、媒体60秒，业务请求128槽、健康检查独立2槽；连接池与部分预算可通过启动配置调整。目录卡片SQL不读取长说明，首页三个栏目不执行无用总数查询。资源预算和查询减少不等于已经获得某个并发容量承诺，最终测试记录需列明负载和错误率。

数据库采用 `internal/maintenance/schema.sql` 初始化及同目录 `migrations/` 有序SQL迁移，以事务、互斥锁及schema_migrations记录避免并发重复应用。本轮分层不修改已有迁移内容或E-R关系。R5首条数据迁移落实2026年11月11日确认的出售元、时日元/日、周月元/月规则，保留来源且不覆盖人工报价。对象存储接入继续暂停；后续恢复时须保留媒体ID、顺序、权限和原图内容散列。小服务器上的并发测试只是当前数据和请求组合的证据，未来容量增长需重新测量。

历史：R5至R13使用标准库net/http路由，业务集中于 `internal/app`；更早记录中的Go1.27.3属于当时构建信息。本轮源码已改为上述Gin分层结构，历史发布结论不自动代表本轮已部署。
