## 当前结构

```text
用户浏览器 → Nginx :5179 → 代码/前端/用户端
                        └→ /api/ → Go public 127.0.0.1:5180
管理员浏览器 → Nginx :5181 → 代码/前端/管理端
                          └→ /api/ → Go admin 127.0.0.1:5182
两个业务API → PostgreSQL qingye_test / Redis6381 / qingye-test媒体目录

独立验收 → Go public 127.0.0.1:5184 / admin 127.0.0.1:5185
         → PostgreSQL qingye_acceptance / Redis6382 / qingye-acceptance媒体目录
```

用户端不包含管理路由或管理代码包；管理端拥有独立依赖、入口、登录与构建。`代码/前端/共享`仅共享纯类型和配置解析，不共享会话状态。历史HTML与React原型归档到`文档/原型代码`，5178继续运行已部署原型；`代码/前端/用户端`是当前用户业务前端，不再以原型命名。

Go按公共展示、账号会话、会员商品、管理配置、媒体及维护任务拆分，并以`APP_SURFACE=public/admin`分别注册入口。数据库保留业务事实、审核记录和推荐分数快照；Redis用于频控与可重建的推荐批次状态。当前媒体存储是可迁移的本机目录，通过统一接口访问；未来改对象存储需要替换存储适配，不改变公开业务ID。完整图解见[架构、E-R与数据流](17-architecture-and-data-flows--架构实体与数据流.md)。

## 入口与会话边界

业务测试环境的两个API共享`qingye_test`库与媒体，便于会员提交后由管理员审核；这不是两个业务库的物理隔离。public不注册管理接口，admin业务接口统一要求管理员身份，也不提供会员收藏、投稿等写入口。

用户会话使用`qingye_session`，管理会话使用`qingye_admin_session`；数据库会话分别绑定`audience=public/admin`，接口同时校验入口、角色、有效期和账户启用状态。上传票据也绑定入口。写请求只允许各自前端的精确Origin，使用Cookie但缺少合法来源的写请求会被拒绝。

**同一IP不同端口不是Cookie域隔离。** 浏览器可能向两个端口发送同一主机的Cookie，因此必须依靠上述服务端校验，不能只靠前端菜单或端口判断身份。当前HTTP使用HttpOnly、SameSite Cookie，`SECURE_COOKIES=false`；切换HTTPS时启用Secure，并配置独立域名和网络访问策略。
