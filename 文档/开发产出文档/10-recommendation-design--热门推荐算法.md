# 热门、个性化推荐与最新上架

更新：2026年11月11日，R12代码实现 ItemCF 商品协同过滤＋属性匹配补齐。热门与最新上架仍沿用R11规则。下列数值为本轮实现参数，可根据后续效果调整，不代表已经验证最优；部署与测试证据见[R12验收](../业务验收与审查记录/ITEMCF-R12--商品协同过滤验收.md)。

## 1 三种排序

| 分区 | 依据 | 无记录时 |
| --- | --- | --- |
| 热门账号 | 有效浏览 × 浏览权重 + 有效收藏 × 收藏权重 | 同分按首次上架时间、ID排列 |
| 为你推荐 | 本人近期浏览作为种子，优先 ItemCF 关联商品，再按属性匹配补齐 | 无个人记录或关闭推荐时回退热门；无有效关联时使用属性匹配 |
| 最新上架 | 首次公开时间倒序，空时间放最后，ID打破同分 | 正常展示可公开商品 |

人工精选轮播独立管理。各分区只在本分区去重；热门商品也可以出现在最新上架中，避免全站去重改变榜单含义。仅展示已公开、审核版本一致、所属分类启用的商品。

## 2 热门规则

默认统计7个北京时间自然日，包含当天；浏览权重1、收藏权重5，每15分钟重新计算。管理员可调整窗口1–30天、权重0–100，并立即触发重算。

- 同一身份、商品、日期只计一次浏览。会员跨会话按账号去重；未登录访客使用服务端签名Cookie。后台浏览和卖家查看自己商品不增加热度。
- 收藏只统计首次收藏处于窗口内、当前仍有效的记录。取消再收藏不会刷新首次时间。
- 不使用旧站展示计数，不虚构成交或点击，不因新品上架加分。旧 `new_bonus` 字段兼容保留，但参与计算的值固定为0；`new_hours` 不再影响排序。
- 批次使用同一截止时刻和数据库事务，互斥锁防止同时重算。超过60分钟的旧分数不继续参与排序，回退稳定的上架时间次序。

算例：默认权重下，100次有效浏览、10次有效收藏的热度为150；新旧商品使用相同规则。

## 3 浏览画像与匹配

画像只表示本站账号偏好，不推断用户身份或人口属性，不使用其他网站数据。

取最近30天中最近看过的50个不同公开商品，按每天的最后浏览时刻赋予衰减权重：

```text
单个商品某天的浏览权重 = 0.5 ^ (距今秒数 / 604800)
属性偏好占比 = 该属性累计浏览权重 / 总浏览权重
匹配分 = 分类占比 × 6 + 交易方式占比 × 2 + 区服占比 × 3 + 价位占比 × 1
```

7天前浏览的权重约为当前的一半。反复刷新同一商品不会生成更多日记录；更新最后浏览时刻只影响兴趣的新近程度，不增加热门浏览次数。

价位按 `floor(log2(金额 + 1))` 分段，并与报价单位共同组成标识。出售总价、日租、月租分别比较；未知单位或无有效价格不匹配价位。此方案优先保证报价含义一致，暂不自动换算日价、月价。

属性匹配用于 ItemCF 同分排序及无关联商品的补齐，属性同分再按热门分、首次上架时间和ID排列。筛选条件始终对最终候选集生效，不用推荐绕过用户选定的分类、区服、价格或公开权限。

## 3.1 商品协同过滤与补齐顺序

后台取最近30天浏览，每个访客最多保留最近50个不同的当前可公开商品。一个访客在多天浏览同一个商品，在共同浏览统计中仍只算一个身份。会员和签名访客身份沿用现有机制；不同Cookie并不等于经过实名认证的不同自然人。后台和卖家自己的浏览仍由现有采集入口排除。

```text
共同浏览人数 = 同时看过A、B的不同访客标识数
基础相似度(A,B) = 共同浏览人数 / sqrt(A浏览人数 × B浏览人数)
保存的相似度 = 基础相似度 × 共同浏览人数 / (共同浏览人数 + 3)
```

至少两个不同身份共同浏览才生成关联。末尾的收缩系数降低少量样本造成的偶然关联；参数2、3均为首版实现值。每个商品只保存分数最高的30个关联，同分按共同浏览人数、目标商品ID排序。不保存访客与访客之间的相似矩阵，也不使用收藏、咨询消息或图片内容训练推荐。

请求时沿用第3节的个人浏览时间衰减，把各商品权重归一化后，汇总 `种子权重 × 商品相似度`。ItemCF候选排除本人近期已看过的种子商品。最终在一次商品查询中按 ItemCF 分数、属性匹配分、热门分、首次上架时间、ID排序：

1. 有有效关联分数的商品优先出现。
2. 没有关联分数的商品按原属性规则排在后面，补齐首页数量及列表分页。
3. 每个商品只占一行，不做两份结果拼接，因此同一批次、相同数据下的分页不会因拼接产生重复。
4. 属性补齐仍允许出现已浏览商品，以保留原完整列表行为；不会把浏览历史变成永久屏蔽名单。

新商品没有共同浏览记录时可通过属性匹配出现。关闭或重置偏好立即影响本人的推荐；下一批训练还会排除已关闭身份及其重置时间之前的记录。既有全局相似度可能包含上一批的聚合贡献，不承诺即时重训或删除历史事实。

## 3.2 计算、存储与故障回退

- public Go进程启动时执行一次，之后每小时重算；支持命令 `qingye refresh-itemcf`。不新增API路由或中间件，不占用Redis缓存。
- PostgreSQL事务锁避免并行重算；固定截止时刻、可重复读事务保证一批使用一致数据。整批删除与写入在同一事务内，只有完成后才替换旧结果；中途错误或取消回滚，不留下半份结果。
- 每次任务最多45秒，SQL单条最多30秒、锁等待最多2秒，`work_mem=4MB`、关闭本任务的并行查询。4MB是每个排序/哈希算子的预算，不是整个数据库进程的内存上限；大中间结果可能使用临时磁盘。超出时间预算时保留旧批次并记录错误。
- 请求最多以50个种子匹配各自30条关联；读取关联预算500毫秒。读取失败、无关联或快照超过2小时，继续使用属性匹配。原始数据库整体故障仍按现有API错误处理，不声称推荐回退能绕过数据库故障。
- 相似表每次替换，仅保存当前快照，行数不超过参与商品数×30。浏览事实表复用现有表，不另存一份点击明细；本轮不删除既有浏览明细。30天是计算窗口，长期明细保留/清理仍需单独维护。
- 推荐接口不返回关联表、共同浏览人数或其他访客标识。原有 `personalization_source=browsing/cold-start/disabled` 保持兼容，`browsing`涵盖ItemCF及属性匹配，不代表每次都命中ItemCF。

## 4 用户控制与身份隔离

- 登录状态使用会员ID的散列，偏好随账号；未登录使用签名访客Cookie的散列，仅在当前浏览器身份下生效。两种历史不自动合并。
- 首页“为你推荐”旁的“推荐偏好”和个人中心均可关闭个性化推荐、重置偏好。
- 关闭后推荐区显示热门，保留明确提示；重置通过时间边界排除旧兴趣，从后续浏览重新形成偏好。重置不删除收藏或最近浏览列表，也不改变独立的热门去重统计。
- 不返回访客散列、其他用户偏好或完整浏览明细。读取返回是否启用、参考商品数及分类概览。
- 首页与集市在登录身份变化时重新请求，防止沿用上一身份的推荐结果。

## 5 数据库与接口

| 数据 | 职责 |
| --- | --- |
| `product_views_daily` | 热门日去重事实；`created_at`保留首次浏览，`last_seen_at`记录当天最近浏览 |
| `views_visitor_date_idx` | 按访客和日期查近期兴趣 |
| `recommendation_preferences` | 访客散列主键、enabled、reset_at、updated_at |
| `product_hot_scores` | 热门批次快照，保存浏览、收藏及分数 |
| `product_item_similarities` | ItemCF有向Top30关联：source_id、target_id、score、common_viewers、batch_id、computed_at；复合主键(source_id,target_id) |
| `site_settings.itemcf_state` | ItemCF版本、批次、计算时间、关联数及本批参数 |
| `site_settings` | 热门配置、批次状态、首页分区展示配置 |

| 接口 | 行为 |
| --- | --- |
| `POST /api/v1/products/:id/view` | 记录去重浏览、更新当天兴趣时间 |
| `GET /api/v1/products?sort=hot` | 热门排序 |
| `GET /api/v1/products?sort=recommended` | 当前身份个性化排序，可结合原有筛选和分页 |
| `GET /api/v1/products?sort=newest` | 首次上架时间排序 |
| `GET /api/v1/home` | 返回独立hot/recommended/newest及personalization_source |
| `GET /api/v1/recommendations/profile` | 当前身份偏好概览 |
| `PATCH /api/v1/recommendations/profile` | `enabled`开关或`reset:true`重置；未知字段拒绝 |

个性化画像按请求从PostgreSQL派生；只有商品之间的聚合相似关系由后台预计算，不共享个人推荐响应。Redis继续用于限流、聊天票据/连接协调/更新通知与热门批次指针；登录会话、消息正文、权限与行为事实以PostgreSQL为准。图片存储接入本轮暂停。

## 6 验收与维护

覆盖会员A/B隔离、匿名身份防伪、30天窗口、关闭/重置、同日浏览去重、下架来源排除、不同报价单位、分页读取及100次并发请求。完整结果见[R11验收](../业务验收与审查记录/PERSONAL-CHAT-R11--推荐分区与咨询修复验收.md)。

默认权重与时间窗口需要结合实际浏览、推荐点击和运营反馈再调整；不要把测试通过表述为推荐效果已经达到最优。存储接入与图片迁移应等用户再次明确恢复后另行开展。
