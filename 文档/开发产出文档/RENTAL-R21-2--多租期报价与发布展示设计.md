# R21-2 发布、租赁报价与商品展示

2026年11月14日。用户授权实现、隔离验证后推送GitHub并部署152测试站。发布结果及真实检查数字另见[R21-2验收](../业务验收与审查记录/RENTAL-R21-2--租赁报价与发布展示验收.md)。

## 业务规则

出售与租赁发布都取消账号结构控件。新商品不写`kind`；编辑时由后端从锁定的旧商品恢复历史编码，不因新界面缺字段而删除旧资料。其他发布字典、会员资料审核、图片上传与生命周期保持原规则。

普通租赁报价可分别填写时、日、周、月，每种最多一条。时段可自定义名称，如包夜、白天、晚间；起止时间成对选填，结束早于开始表示跨午夜。没有明确时间的旧“包夜”只保存名称，不能擅自补时刻。

时段支持整段包价和段内按时、日、周、月报价。例如白天8元/小时、包夜20元/时段、每日07:00–19:00按周140元可同时表达。系统保存原金额，不乘小时数或折算季、年价格。命名时段也可表达标题明确写出的双周、季度等整段价格。每商品最多12条时段报价，同名称、起止时间和计价方式不能重复。普通报价与时段报价互不覆盖。

“时日／周月”是管理员安排的展示分类，与金额、报价单位独立。会员不能写此字段；管理员审核通过或直接上架租号时必须有有效分类，可以在同一操作中分配。旧租号只根据明确的原分类初始化，不根据主价猜分类。

## 字段与接口

| 字段 | 含义与边界 |
| --- | --- |
| `rental_quotes[].unit` | `hour/day/week/month/period` |
| `amount` | 元，十进制字符串，最多两位小数；沿用现有金额范围 |
| `label` | 仅时段，1–30个有效Unicode字符，去首尾空白、不含控制字符 |
| `billing_unit` | 仅时段，`period/hour/day/week/month`；省略按整段处理 |
| `start_time/end_time` | 仅时段，可均省略或合法`HH:mm`成对填写，不可相等 |
| `rental_category` | 顶层`hour_day/week_month/空`；会员写请求携带非null值返回403 |
| `price_unit/price_amount` | 兼容主价，取报价数组第一条；时段主价必须有完整明细 |

管理员保存时省略分类表示保留，空字符串表示清空。清空后不能上架。修改分类与商品版本、审核快照、发布任务和审计保持同事务，不拆成先改分类后审批。新咨询消息保存完整报价及分类快照，旧消息不重写；双端聊天按快照的时段名称、时间和计价单位展示。

## 筛选与展示

账号租赁列表上方原数量栏改为全部租号、时日、周月。查询参数`rental_category`只接受固定枚举。切换出售时清空租号条件。分页显示“第X页，共Y页”，仍由接口总数和游标计算，不向用户显示每页条数或账号总数。

卡片展示普通报价，并按各自计价单位分别概括时段最低价；同一计价方式存在多档时标“起”，详情显示完整档位。不能跨单位比较8元/小时与20元/包夜。手机保持两列、桌面三列，长时段名称允许换行。

`price_unit=period`时同时使用`period_basis`，默认`period`。预算与排序取同计价方式时段的最小金额；没有该方式报价的商品不匹配，不能回退到另一方式的主价。普通报价筛选沿用自身单位，不把仅限白天的小时价伪装成全天普通小时价。公开搜索SQL参数化，排序分支固定。

## 数据演进与标题拆价

新增迁移`0017_rental_quote_periods.sql`，保留0016及以前迁移。扩展数据库单位约束，新增带租售约束的分类字段和公开索引。已有非空租赁单位配置追加时段；空配置继续表示不额外限制。旧分类初始化递增版本，并同步原本已批准的版本，保持可见性和首次上架时间，历史审核快照不改写。

[拆价工具](../../代码/工具/split_legacy_rental_quotes.py)默认只生成私有预览。仅处理原始来源为legacy、仍是R5价格和分类、报价数组为空、版本未有人为编辑的记录。0017前后分别校验基线版本2／3。简单连续价格自动解析；带时间条件、不同档期、残余数字或冲突金额的标题要求逐条核对，以完整标题SHA256绑定私有报价清单。真实标题清单和数据库备份不入Git。

应用前重新生成并比较完整计划，执行数据库备份。实际SQL持有商品写锁和分类共享锁，逐条比较旧投影；任何并发修改使整笔回滚。更新主价、多报价和版本，同时保留旧原价、原分类、原始载荷、标题、图片关联和历史审核。每条审计包含旧值、新值、人工核对说明、计划和核对清单散列。再次运行会跳过已处理记录。

## 验证与回退

功能、受控并发、安全检查只在`qingye_acceptance`。业务测试库仅执行已授权的精确迁移，发布后只读核验。部署前备份、源文件清单、三端产物散列、进程实际可执行文件及HTTPS资源均须核对；5178原型保持masked，生产8.140不部署，短信配置不改。

新增时段资料已经存在后，旧API不能完整编辑或展示新字段。回退应使用理解新契约的兼容版本；不能仅切回旧二进制就视为恢复完成。数据库、媒体与私密资料密钥按既有恢复流程分别保留，不自动用旧备份覆盖后续业务操作。
