# R15 PostgreSQL 数据库审查

日期：2026-11-12。范围为 R15 工作区及基线 `b83515a` 中的 PostgreSQL 存储层、领域校验和有序迁移。没有操作 8.140 生产数据库；以下回归使用专用测试数据库中的独立 schema，结束后清理。此记录不是线上压力测试报告，也不替代发布后的全量验收。

## 已修复的问题

| 问题 | 证据与影响 | 修复 |
| --- | --- | --- |
| 图片追加存在反向锁序 | `MemberStore.AppendImages` 原先按请求的图片顺序逐个 `FOR UPDATE`。同一会员向不同商品并发追加 `[A,B]`、`[B,A]`，可形成互相等待。 | 一次按媒体 ID 稳定排序锁定整批，再按请求顺序插入，保留展示顺序。数据库错误不再被误包装成“图片未就绪”。 |
| 分类属性可占用专用字段名 | 分类配置原先接受 `custom_tags`、`private_credentials`、`qq_account` 等，和独立的标签、私密资料表单冲突。 | 配置校验禁止这些保留字段；产品写入与配置写入共用私密键识别。保留已有 `game`、`tags` 普通历史字段的兼容。 |
| 自收藏和停用账户收藏增加热门分数 | 真实数据库回归在修复前得到 `score=20, favorites=4`：卖家本人、正常会员、停用会员和管理员各一条收藏全部计分；正确结果应为 `score=5, favorites=1`。 | 保留收藏功能，仅热门统计排除卖家本人、停用账户及非会员角色，和首次咨询计分口径一致。 |
| 多租期报价绕过模板单位限制 | R15 初版租赁校验未检查分类单位，发布允许的单位和集市筛选不一致。 | 非空 `category.price_units` 同时约束主报价及每条 `rental_quotes`。收窄模板不隐藏旧公开商品，但编辑、复审必须符合新规则。空数组沿用历史“未设置额外限制”语义。 |

## 事务、版本和可见性复核

- 商品编辑、审核和图片修改持有同一商品行锁，并校验 `expected_version`；编辑后转草稿、递增版本并清空审核版本。分类规则读取持有共享锁，配置修改持有排他锁，避免商品提交使用被并发移除的选项。
- 自动编号使用每个租售前缀的事务级 advisory lock，加非事务 sequence；回滚可能产生跳号，不复用已分配号码。编号最大值查询有匹配的部分表达式索引，支持空库迁移后再导入旧编号的情况；没有修改历史重复编号。
- 图片追加的幂等键和图集写入在同一事务中；本轮统一媒体锁序。图片重排为一次批量更新。公开及会员图集分页在只读 `REPEATABLE READ` 快照中读取版本和图片，避免拼接两次编辑的数据。
- 公开列表、详情、推荐和媒体可见性均检查 `published`、`approved_version=version` 及分类启用状态。收藏中已停止公开的商品只返回占位内容。公开字段使用白名单，私密凭据不在商品 JSON 或审核快照表中。
- 私密 QQ 资料独立加密存储；管理员显式读取只审计操作者、商品和时间，不记录明文。涉及凭据的创建幂等摘要使用部署密钥 HMAC，避免以无密钥的请求正文摘要保存可猜测口令的校验材料。
- 数据迁移与基础结构共用事务和迁移锁，已登记版本不重放。`0005` 保留原始载荷及旧编号，`0006` 会话合并由主审维护；本轮未修改聊天合并逻辑。

以上是代码与回归审查结论，不表示所有 PostgreSQL 竞态均已穷尽。

## 后续维护建议

- 当前商品和媒体索引满足已有查询结构；本轮没有获取线上 `EXPLAIN ANALYZE` 或声称新增性能百分比。数据量增长后按慢查询证据评估搜索索引与分页策略。
- 过期会话、短信挑战和幂等记录尚需明确保留期限及定期清理策略。幂等记录不能直接按短 TTL 删除，否则可能改变旧请求重试语义；本轮未擅自清理数据。
- 批量补导旧商品属于维护操作，应安排在停止新增商品写入的维护窗口。现有编号测试覆盖“导入已提交后分配”和并发新建，没有验证在线补导与新建交错时的历史编号冲突处理，不应将该情况宣称已支持。
