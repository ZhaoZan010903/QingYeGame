## 分层性能证据

同一份576商品 / 48,332媒体引用数据，API限50条。服务器原图迁移同时运行。本机脚本为只读，20次API请求拆成10次顺序和10次最多5并发；SQL使用 `EXPLAIN (ANALYZE,BUFFERS)`，没有改动业务数据。

| 测量位置 | 结果 |
| --- | --- |
| 服务器本机顺序API | 中位12.833ms，P95 19.887ms，0失败。 |
| 服务器本机5并发API | 中位52.616ms，P95 79.643ms，0失败。 |
| 数据库公开数量 | 1.3–2.1ms。 |
| 数据库分页ID | 约1.35ms。 |
| 数据库原完整JSON分页 | 10.0–10.6ms。 |
| 数据库原热门分页 | 11.8–24.1ms。 |
| 先前外网、未请求gzip、5并发20请求 | 中位1.950秒，P95 8.764秒，0失败。 |

两个测量层的差异不支持“数据库导致外网秒级尾延迟”的结论。基线采样时可用内存约1.0GiB，未见数据库等待。网络传输、客户端环境和原图迁移流量需要在部署阶段分开测量；20次样本也不是容量承诺。

目录响应原107,947字节中，重复介绍占28,268字节；公开列表移除该字段预计减少约26%未压缩响应体，完整标题及详情不变。Nginx已启用 JSON gzip，后续外网对比应明确请求gzip并记录压缩后的传输字节，不能拿identity和gzip样本混为同一种测量。没有引入可能延迟反映下架状态的整页缓存。

无敏感内容的原始基线报告保存在部署私有目录 `qa/server-performance-baseline.json`，不将源商品、凭据、会员资料或生产快照提交仓库。

## 管理接口隔离独立复核

复核了 `app.go`、`auth.go`、`media.go` 及相关集成检查：

- 公开与管理进程分别注册路由；公开端不包含管理写入口，管理端不包含会员发布写入口。
- 独立Cookie名之外，服务端还同时验证session audience、用户角色、启用状态及有效期；重命名或复制Cookie不能跨端使用。
- 管理进程在登录与健康检查之外使用统一管理员门禁，覆盖只读预览和媒体。
- 上传票据接收及完成阶段均核对所属端；公开Origin与管理Origin分别精确校验。
- 原会话按public迁移后，原管理员会话也因角色条件不能登录公开端；需在管理端重新登录。

本次独立复核未发现新的跨端绕过。后续仍需在真实双端代理部署中执行浏览器、并发与安全测试，作为下一轮验收证据。
