# MEDIA-R20 -- 业务数据库与Redis审查清单

日期：2026年11月13日。状态：检查设计与后端同版、核心浏览器结果已分别记录，三端已部署152测试环境。当前后端338项全量/race、45项重复三轮、真实300图及物理回收证据见[隔离验收记录](MEDIA-R20-ACCEPTANCE--商品媒体隔离验收记录.md)；本清单不因总体测试通过就自动全部勾选。用于R20实现期间的独立复核，不是测试通过报告。范围以[图片需求](../前期设计文档/MEDIA-R20--商品图片上传存储与展示需求.md)、[Go安全设计](../开发产出文档/SECURITY-R20--Go安全模块设计.md)和[实施清单](../计划/MEDIA-R20--实施与验收清单.md)为准。

## 1 隔离环境与证据

- 写入、到期删除、故障注入和并发测试只使用独立acceptance数据库、Redis和媒体根目录/桶前缀；不得指向152现有业务原图、历史OSS复制目录、8.140或5178原型。
- 所有真实上传与往返测试图使用1—10KB的合成有效图片，名称与内容包含可辨识序号，不能用真实会员图片或原图库做压力输入。300张控制在约0.3—3MB原始载荷；记录实际大小和散列，不将小文件结果外推为大图带宽或解码容量。
- 超尺寸/像素、错误长度及格式场景使用小型构造输入、受控Reader或模拟故障；若未测真实大图，应在报告明确未覆盖，不能为凑结果扩大上传量。
- 测试前后记录数据库迁移号、代码提交或源码散列、有效配置摘要、对象数量/字节及进程。输出不得包含Cookie、上传票据、完整签名URL、QQ资料或云凭据。
- 两个会员、至少两个管理员及不同用途媒体作为权限对照；测试ID和文件清单属于本轮fixture。清理仅接受明确fixture清单，失败时保留证据，不递归清空共享目录。
- 当前旧OSS读取预备保持disabled；新链路只接入明确登记的R20新商品媒体。CDN域名尚未解决，浏览器直连存储/分发的实测与CDN防刷验收分开记录。

## 2 第一轮：业务、数据约束及接口投影

| 编号 | 场景 | 必须观察到的结果 |
| --- | --- | --- |
| B01 | 两端分别选择/拖入1、50、99、100、101张 | 1—99合法；100及以上整批拒绝，浏览器无上传请求、无部分加入队列。若有批次申请API，100项同样无部分DB/对象落地 |
| B02 | 同商品按99＋99＋99＋3追加300张 | 关联恰为300个有效有序媒体，可继续合法追加；99是单批边界，不是商品总张数上限 |
| B03 | 乱序完成、跨批次移动、设封面、失败重试、保存刷新 | 排列由稳定媒体ID及显式顺序决定，不由网络完成时间决定；排序不复制对象，不重复关联 |
| B04 | 并发编辑排序或追加 | 按预期版本返回成功或明确冲突，不静默丢图；API、预览、刷新后的封面/数量/顺序一致 |
| B05 | 会员A引用B的上传、伪造用途/入口、chat或avatar用于商品 | 在持久关联前拒绝；不泄漏私有对象键与资源是否存在，不改变B或聊天记录 |
| B06 | 审核通过、新图上传尚未同步完成 | 用户只见“上架中”等业务状态；完成前不公开该版本，不因单张已传成功提前发布 |
| B07 | 用户端列表、详情、上传、商品状态及错误响应 | 无迁移阶段、提供方内部状态、重试堆栈、物理目录、管理动作；签发的受限访问URL按接口用途返回，不作为管理元数据混入DTO |
| B08 | 管理端看同一任务及用户冒用管理接口 | 管理员能看必要状态/原因与受控重试，会员被拒；管理端也不显示密钥或原始签名凭据 |
| B09 | 草稿/待审/审核中/退回与最终驳回 | 按已落地事件表计算五天；普通保存、刷新和重复提交不续期。最终驳回不新增保留期；过期提示和重新补图流程完整 |
| B10 | 下架、OSS五天、迁回成功、ECS五天 | 下架先停公开授权；五天后校验迁回再删OSS；第二窗口从成功迁回起算；失败保留源副本 |
| B11 | 旧商品、旧原图、客服/头像/聊天引用 | 读取和原路径不因R20切换；不依据历史创建日期纳管或立即清空；旧R19用途权限保持 |
| B12 | 数据库约束审阅 | 批次/媒体归属、幂等键、顺序、状态枚举、租约版本、精确对象代次和外键明确；迁移默认值不把历史媒体误标成R20可清理 |
| B13 | 第4天退回延长图片至第9天，再编辑保存为草稿 | 旧第5天草稿截止不能提前清理仍在有效退回窗口的媒体；普通文字保存不反复续期，主动删除仍按明确删除意图执行 |

对B01：旧版逐图申请接口无法识别浏览器原始选择批量，不得仅测单图接口便宣称服务器已校验批次大小；是否新增批次接口必须在契约中如实说明。对B09：尚未确定的计时事件应先明确实现规则，再写断言，不能由测试悄悄定义业务。

## 3 第二轮：数据库、文件和任务并发

| 编号 | 故障或交错 | 必须观察到的结果 |
| --- | --- | --- |
| C01 | 同一任务重复申请、分片、完成回调；同幂等键不同内容 | 相同重试返回确定结果；不同载荷冲突；媒体、关联、占用与审计不重复 |
| C02 | 慢上传/断网时同时执行普通查询 | 网络接收不长期占DB连接或行锁；中断可恢复，重复请求不突破声明/实际字节与并发限制 |
| C03 | 取消/停权与接收、完成、关联并发 | 按统一锁序及安全版本形成确定先后；撤销后的请求不能重新安装或关联文件，旧凭据不复活 |
| C04 | 账号A停上传后清理，B同时上传 | 只处理A的ECS商品暂存，B、OSS已上架图、历史素材及有效聊天/头像不受影响；停上传不等于退出全部登录 |
| C05 | 同步中断、校验不一致、OSS超时、目标成功但DB提交失败 | 不删除唯一有效源；重试查询精确对象和持久记录，不靠猜测标成功；不会将部分图集公开 |
| C06 | 目标已校验但源删除失败、重复删除、进程重启 | 保持待清理/重试事实；不能误报已单份；按精确对象键与代次重试，不扩大前缀 |
| C07 | 下架五天内重上架或已迁回后重上架 | 取消尚未执行的旧任务；后者重新同步校验。旧商品版本任务不能删除新版本有效对象 |
| C08 | 删除已发出后租约过期或用户重新上架 | 删除中的物理键不可被复用；在途I/O先对账，不能仅靠再次查DB或过期Redis锁宣称撤回；新对象使用新的不可复用代次 |
| C09 | 任务多worker竞争、崩溃、重复领取与过期旧worker返回 | 所有权/租约和版本防止旧worker提交；有界批量、重试次数及退避，不全表扫描或无限重试 |
| C10 | DB不可用/事务回滚/管理员并发恢复上传 | 无法验证权限或状态时拒绝危险动作；关键处置与审计事务一致；恢复不复活撤销任务，不依靠缓存执行新删除 |
| C11 | 资源被商品/审核快照/客服等多处引用 | 引用冲突进入明确待处理，禁止误删。关联与删除使用同一受控媒体状态，不能先检查后被另一事务重新关联 |
| C12 | 新迁移前后schema、索引与SQL计划复核 | 外键/唯一约束/状态约束实际生效；任务扫描按状态/时间/键有界；无持锁HTTP传输，无复制全部媒体到内存 |
| C13 | 停权清暂存与StageCandidate登记并发 | 采用一致所有者/媒体锁序；停权已提交时拒绝或立即纳入清理，登记先完成时停权能使候选立即到期，不能额外保留五天 |

有外部文件或对象操作时，数据库事务不能提供跨存储原子性。报告必须展示“操作已执行但结果未提交”的恢复证据，不能只证明正常成功路径。五天边界用隔离fixture/注入时钟演练，禁止修改共享环境真实期限。

## 4 第三轮：Redis、资源防护及回归

| 编号 | 场景 | 必须观察到的结果 |
| --- | --- | --- |
| S01 | Redis计数首次创建、并发、窗口边界、重复拒绝 | 计数与TTL原子，拒绝不无限续期；窗口边界突发被设计范围覆盖；无无限维度key或长期无TTL记录 |
| S02 | Redis不可达/连接池满/重启 | 新增上传及依赖防护的高风险操作明确503，不无限放行，也不误判恶意；数据库持久停权不会消失 |
| S03 | PG任务租约/过期owner回调；未来Redis分布式租约另验 | 只能释放本租约；过期owner不能提交受保护业务状态；本机信号量和分布式容量不混称 |
| S04 | 正常四批300图、共享IP、多账号、失败重试 | 不因普通上传请求数累计触发持久停权或清图；允许退避但有恢复路径；恢复/续签不绕过原有资源上限 |
| S05 | 伪造X-Forwarded-For、跨Origin、跨surface会话/票据 | 拒绝伪造身份与跨入口复用；不能从客户端任意header派生受信账号/IP |
| S06 | 小型伪图片/异常像素头/错误长度/路径与符号链接 | 在真实解码和受控路径边界拒绝；不展开任意URL、目录或前缀；失败无越界读写 |
| S07 | 当前original访问及私有/公开切换；历史缩略图独立回归 | 两条路径均按当前用途和业务状态授权；下架不再签新公开地址；旧链接窗口明确，无私有缓存串用 |
| S08 | 当前授权限频；实际下载防刷作为后续，取消小图降级 | Go签名接口限制与实际下载入口分别验证；边缘未接入标未覆盖，不通过裸OSS/ECS兜底绕过防护 |
| S09 | 日志风暴、审计失败、敏感错误内容 | 普通拒绝日志有界/聚合；关键审计失败不接受处置；用户DTO、监控标签、日志不含敏感凭据或完整签名URL |
| S10 | SeaweedFS低水位、对象删除及卷回收 | 拒绝新增占用时保护唯一副本；对象删除和物理回收分别计量，压缩留空间；私有服务端口不外泄 |
| S11 | 性能优化后的两端真实流程 | 桌面/手机可用，300图按需渲染、及时释放预览URL；正常浏览/排序无重复上传，用户无技术状态暴露 |
| S12 | 全量回归、竞态、依赖检查 | 本轮源码与产物对应；Go使用既有构建标签；R19聊天/头像/转接权限、首页缓存、会话隔离保持，结果与跳过项如实记录 |

性能记录至少包含同数据、同安全规则下的p50/p95、错误率、DB连接等待、Redis耗时、队列长度、CPU/内存、实际上传字节和首图耗时。1—10KB样本仅支持小图队列与业务结论，不宣称大图吞吐、3Mbps链路上限或生产容量。
