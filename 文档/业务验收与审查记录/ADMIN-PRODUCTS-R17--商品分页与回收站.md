# R17 商品管理分页与回收站

日期：2026年11月12日。用户要求将管理端商品页整理为分页列表，补齐增删改查，增加上架时间等信息。修改涉及管理 React、Go 管理接口和迁移0009；用户端样式与页面不变。

## 页面与操作

商品管理、待审核页均使用服务端分页，每页20或50条，提供页码、前后页和页码跳转。查询条件保存在地址栏；编辑关闭、详情返回、浏览器前进后退保留筛选和页码。删除造成末页为空时，自动回到有效末页。页面不再追加“加载更多”。

| 区域 | 展示与行为 |
| --- | --- |
| 商品信息 | 封面、最多两行标题、编号、租售类型、区服与角色性别；缺少封面或加载失败显示占位 |
| 报价 | 金额与单位相邻显示；租赁显示报价档数，未填写报价保留联系客服 |
| 来源 / 状态 | 平台录入、会员投稿或旧站迁移；草稿、待审核、已上架等状态 |
| 图片 / 咨询 | 图片总数、累计咨询人数 |
| 时间记录 | 首次上架、最近更新、创建时间，统一北京时间；从未上架显示“尚未上架”；回收站改为展示删除时间 |
| 筛选 | 编号或标题、状态、来源、租售类型；按最近更新、首次上架或创建时间倒序 |
| 管理 | 新增、查看、编辑、上架、下架、删除；回收站提供恢复草稿 |

电脑使用六列表格，手机改为分组信息块。时间、编号、金额、数量使用等宽字体。新操作对话框明确说明后果；下架和删除必须填写原因，提交期间禁止重复操作。

“上架时间”沿用现有首次公开时间，不以重新上架时间替换。删除是可恢复删除，资料、图片、咨询历史和加密交接资料保留；恢复只回到草稿，不能自动上架或绕过会员审核。不提供永久删除或清空回收站。

## 接口与数据变化

`GET /api/v1/admin/products` 新增 `page`、`trade_type`、`sort`、`trash=1`。返回原有 `data/total/next_cursor`，增加 `page/page_size`。旧游标调用保留，但禁止同时传page和cursor。单页最多50条、偏移最多1,000,000；筛选枚举精确校验，排序列固定，查询值使用SQL绑定参数。

列表只读取封面和列表字段，不读取长说明或完整图片集；完整信息继续从详情接口获取。三个日期来自数据库。`deleted_at/deleted_by_admin`仅供管理使用，公开字段白名单不暴露内部删除标记。

| 接口 | 输入 | 结果 |
| --- | --- | --- |
| `DELETE /api/v1/admin/products/:id` | `expected_version`、非空`reason`，原因最多500字 | 移入回收站，停止公开，版本递增 |
| `POST /api/v1/admin/products/:id/restore` | `expected_version` | 恢复草稿，清除批准版本，版本递增 |

迁移`0009_admin_product_trash.sql`增加`products.deleted_by_admin boolean NOT NULL DEFAULT false`、删除状态约束和回收站排序部分索引。原`deleted_at`还用于会员草稿清理墓碑，不能把所有墓碑都显示为可恢复商品。只有管理员回收的完整记录可恢复；已经清理资料的会员墓碑返回404。恢复从未公开的会员新草稿时重新设置72小时期限，其余商品保留原生命周期边界。

删除、恢复在单个事务内锁定商品行，校验操作者所见版本，写入`product.trash/product.restore`审计。并发修改返回409，不通过重新获取最新版本强行覆盖。图片关联不解除，已有媒体GC因仍有商品引用而保留文件。公开展示、轮播与推荐继续按数据库可见性过滤。
