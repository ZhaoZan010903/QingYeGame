## 第3轮明确检查点

| 检查对象 | 检查内容与结论 |
| --- | --- |
| 双入口及Cookie | 对照`app.go`、`auth.go`、Nginx与环境生成脚本。用户/管理按不同surface注册；管理预览与媒体也经统一门禁；Cookie名称之外校验audience、角色、启用状态和精确Origin。相同IP不同端口不是Cookie域隔离，IP/HTTP仅为当前确认的测试方式。未发现新的跨入口绕过。 |
| Nginx CSP与代理 | script/connect/font限制同源，禁止object、base和被嵌入；style允许inline以兼容当前React样式。用户站API不回退到SPA，两个站点只代理各自loopback端口。没有宽泛CORS或直接静态公开媒体目录。 |
| gzip与缓存 | 两端JSON/CSS/JS启用gzip并带Vary；用户静态哈希assets长缓存，其余no-store；管理站全站no-store。API与媒体不使用整页公开响应缓存，不能把静态缓存策略套到权限数据。 |
| 日志 | access log使用`$uri`而非完整request/query，不记录Cookie或上传票据。Nginx错误日志不等同于这份访问日志格式，仍必须作为私有运维资料保管；本轮不声称任何异常日志都已逐字段脱敏。 |
| systemd与权限 | API非root运行，ProtectSystem/ProtectHome/NoNewPrivileges开启，仅媒体目录可写；Nginx单独临时及日志目录。验收独立OS用户、DB角色、Redis实例和媒体路径，不共享验收写数据。迁移服务只允许媒体和导入目录写入，reconcile仅本地读文件更新DB。 |
| 迁移来源与字节 | 源URL只补全协议后生成确定性key；逗号仅在下一URL开始处切分，不截断OSS参数。初始与跳转来源受限，校验图片签名、长度、最大字节和磁盘余量；下载原字节与缩略图分别存储。断点清单跳过前检查大小，最终独立rehash用于识别同长度损坏。 |
| 完整图库核验 | source ID保留独立商品；同商品重复URL按导入器规则去重、跨商品可共享原文件。检查每张本机原图、清单、媒体状态/大小/散列及每商品关联顺序；报告只保留计数和不可逆定位值，不含源URL或商品载荷。 |
| 备份与恢复 | `check_database_restore.py`只备份专用测试库，用随机新建库恢复，只有本次成功创建的临时库可被清理，不覆盖已有库。dump使用私有目录与0600文件；比较指定表计数和旧商品字段摘要。源库比较与pg_dump不是同一快照，若有并发修改可能要求重跑；不是所有字段逐项比对，也不是原图或异地备份。 |
| SQL与公开投影 | 关键词、筛选值、属性key、ID、分页均以SQL参数传递；排序与操作符来自固定分支。商品使用明确JSON投影，公开出口删除审核备注及内部版本字段；原始载荷、所有者ID和旧图片来源不公开。 |
| 审核快照 | 快照存储当前产品资料及有序图片ID，排除legacy原始载荷；含内部字段的快照仅在管理员边界内使用，历史图集接口只投影图片ID/alt/status/受控URL。公开接口不直接序列化审核表。 |
| 推荐与Redis | 固定截止时刻、北京时间自然日、未来数据排除、legacy新品分为0、同分稳定排序、当前可见性筛选与60分钟旧分数回退保持一致。推荐重算锁、请求幂等与统计去重位于PostgreSQL；Redis实际为限流与批次指针，不宣称已实现整份商品缓存。见[实际与建议缓存图](../开发产出文档/17-architecture-and-data-flows--架构实体与数据流.md)。 |

以上结论针对已检查文件和当前同源代理结构；不扩展为任意部署方式或所有异常情形的保证。
