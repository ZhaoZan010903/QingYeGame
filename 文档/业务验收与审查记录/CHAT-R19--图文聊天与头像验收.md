# R19：图文聊天与头像验收

日期：2026年11月12日。状态：三端已发布152测试环境，源码和文档随本提交同步私有GitHub。发布号`20261112-chat-images-r19`。本记录对应[R19需求](../前期设计文档/CHAT-R19--聊天界面与图文消息需求.md)与[实现设计](../开发产出文档/CHAT-R19--图文聊天与头像设计.md)。

## 1. 已交付内容

| 范围 | 实现 |
| --- | --- |
| 聊天界面 | 会话列表、接待信息、咨询商品、消息区和输入区分层；用户端深浅主题，管理端清晰浅色工作区 |
| 图＋文 | 添加图片或粘贴截图，预览、上传进度、移除与失败重试；纯文字、纯图片和多图配文字均支持，图文作为同一条消息保存 |
| 气泡 | 本人靠右、对方靠左；昵称、客服身份、头像、时间和发送状态；长文本换行、时间间隔、图片网格及大图切换 |
| 头像 | 消息页左侧顶部更换本人头像、恢复默认；列表和消息使用头像，无头像或图片失败时显示昵称首字 |
| 手机 | 单列对话和返回咨询列表；320/390px布局无横向溢出，输入区和发送按钮位于可视区域 |
| 原有能力 | 咨询商品入口、R18列表/历史游标、通知与重连、WebTransport优先及同源WebSocket兼容保留 |

一次最多9张，聊天单图10 MiB、头像2 MiB，均支持JPG/PNG/WebP；正文最多2000个Unicode字符。这些是消息资源边界，不是商品图片总量限制。暂未加入头像手动裁剪、语音、视频、文件附件或离线持久草稿。

真实数据库与媒体服务测试覆盖：申请上传、图片解码重编码、完成上传、图文原子保存、纯图片、附件顺序、幂等重放及409冲突。WebSocket发送后以WebTransport重试返回同一消息，WebTransport新图片消息也通过；8次同意图并发重试耗时29.89ms，只产生一条持久消息。

权限测试覆盖未登录、无关会员/管理员、其他会话、非聊天用途、未完成图片、未发送预览、发送后双方读取、客服转接撤权、头像本人绑定与重置、外站Origin拒绝。原图和缩略图共用权限判断；管理端不能把聊天图片追加到公开商品。GC检查确认消息附件与当前头像不会按废弃上传清理。

## 3. 浏览器验收与限制

Chrome通过本地正式构建预览连接独立验收API，代理设置保持原状。隔离HTTP预览下实际页面采用WebSocket；WebTransport图文由真实协议集成测试验证，不能把该浏览器结果表述为公网UDP连接验证。

- 用户端粘贴截图并附文字发送，管理端收到；管理端回复文字及两张图片配说明，用户端收到。刷新后重新读取成功。
- 图片点击打开大图，方向键切换2/2到1/2，Esc关闭；文字与图片保持在同一气泡中。
- 头像经真实上传/完成/资料接口设置，两端页面显示已保存头像，所有可见头像图片完成加载。
- 用户端桌面深浅主题、320×640与390×844检查；管理端390×844检查。调整了重复顶部留白、手机导航拥挤及输入区被推出视口的问题。
- 浏览器检查最后使用正式静态构建，已恢复测试前的桌面尺寸和用户端深色主题。

**自动化限制：** 本机Chrome扩展未开启文件URL访问权限，无法用自动化选择本机文件；未改动扩展权限。因此“点击图片/头像按钮后，从系统文件窗口选取文件”的完整自动操作未验证。截图粘贴上传、实际上传接口、头像绑定和页面显示已经验证；标准文件输入事件经过代码检查。后续用户试用可重点检查这两个文件选择入口。

截图和原始验收日志存于工作机与服务器私有验收目录，未将聊天样本、图片或日志提交仓库。

## 5. 三轮审查

1. **数据与权限边界：** 检查用途、会话绑定、附件所有权、已完成状态、重复关联及重试顺序；新用途读取不再经过管理员无条件放行分支。
2. **并发与资源生命周期：** 检查会话/媒体锁、事务、唯一约束、上传额度、GC引用、商品/客服公开媒体入口与Origin保护；真实集成和竞态测试通过。
3. **页面与交付：** 检查身份切换后的异步响应隔离、旧消息兼容、两端路由、手机输入区、主题和正式产物；核对迁移前备份、原字段摘要、实际运行二进制及HTTPS资源。
