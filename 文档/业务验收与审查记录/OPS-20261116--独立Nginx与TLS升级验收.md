## 旧站上游 HTTPS

旧站 API 与 CDN 从原 HTTP 上游改为严格 HTTPS，分别固定其 Host 和 SNI，开启 `proxy_ssl_verify on`、校验深度 4，限定 TLS 1.2 / 1.3。API 不带尾斜杠和 CDN 带尾斜杠的原路径语义保持，真实只读响应散列对比通过。

上游链补齐使用 Let's Encrypt 官方 Root YR-by-X1 交叉签名证书，仅写入独立入口专用 `/etc/qingye-edge/upstream-ca.pem`。准备工具检查固定 DER 指纹、证书有效期及现有系统信任链；系统 CA 文件未修改，也未关闭上游证书校验。

这次加密升级保护入口到供应商的链路，旧站外部 SaaS 的数据和系统控制权仍属于原供应商，不属于新版清叶数据库接管或业务迁移。

## 证书与访问边界

IP 证书仍使用原 lineage 和生产 TLS 版本指针。续期 hook 已适配独立入口：校验新配置、reload edge，再在证书确实变化时重启 Go，使 WT 读取新证书；原 timer 与运行保护保持，增加独立入口所需的目录权限。失败回退和证书未变化时不重载的逻辑有单元测试覆盖。

旧站使用复制保留的 Certum 证书，读取 `/etc/qingye-edge/tls/legacy/{fullchain,privkey}.pem`，有效至 **2027-04-14**。该证书仍需手动维护，未完成自动续期接入。未来如改用 `qingye-legacy`，必须单独实现证书成对发布、校验、加载和回退；当前 IP / 新域名脚本不负责它。
