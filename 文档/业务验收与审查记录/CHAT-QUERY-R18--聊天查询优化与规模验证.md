# R18 聊天查询优化与规模验证

2026年11月12日。针对消息增长后的查询成本，优化现有PostgreSQL查询、索引和会话分页。用户端、管理端与API已部署到152测试环境，发布号`20261112-chat-query-r18`。

## 1. 改动与保留规则

- 最后一条消息的编号、正文摘要、发送人合并为一次LATERAL查询；列表先取51条候选，再对实际返回的50条生成摘要，避免深分页计算被跳过行的摘要。
- 总会话数、总未读数、当前页在一个SQL语句的同一数据库快照内读取。每个会话的未读范围只统计一次，当前页复用结果。
- 商品数量改为先去重再计数，新增商品快照ID表达式索引；缺少ID的快照不计入，重复咨询同件商品只算一件。
- 列表支持游标，按`updated_at DESC,id DESC`排序；同更新时间使用ID倒序保证确定顺序。消息正文原有`before/after`分页未改变。
- 两端使用新游标；保留旧`offset/next_offset`兼容。实时刷新首页不重置已展开页的游标，保留从首页移出的已加载会话，并拒绝账号切换前的迟到分页响应。
- 保留当前归属校验、单会员主会话、历史别名、逐消息商品快照、发送幂等、事务锁、已读不越过已展示消息以及转接后旧客服失权。

这次没有新增数据库、业务表或持久化统计字段，也没有把聊天正文加入Redis。总未读统计仍随未读范围增长，商品去重仍需处理对应会话的商品记录；不能将本轮结果理解为任意数据量下耗时恒定。

## 2. 接口兼容

HTTP入口保持`GET /api/v1/chat/conversations`、`GET /api/v1/admin/chat/conversations`；WebTransport与WebSocket继续共用`list`指令。

```json
{"cursor":"服务端返回的不透明游标"}
```

HTTP同名查询参数为`cursor`。第一页不传游标，返回`data/total/unread/next_offset`及新增的`next_cursor`；终页`next_cursor=null`。旧请求仍可传`offset`，非零offset不能与游标混用。

游标包含微秒精度时间、会话ID与兼容位置，限制长度并检查格式。它只决定翻页边界，不赋予会话访问权限；每次查询仍按当前用户、入口与接待归属过滤。列表是实时列表，不是跨多个请求冻结的历史快照；期间活动会话可能上移，前端合并去重并持续刷新首页。

| 索引 | 用途 |
| --- | --- |
| `chat_admin_inbox` | 管理员当前主会话按更新时间/ID倒序访问，不再要求状态字段参与排序 |

0010在原迁移事务中创建索引；本次业务库聊天数据很少，采用备份、短暂停止双API、迁移后启动的方式。以后大表执行同类索引建设，应另行安排并发建索引和锁等待验证，不直接照搬本次停机时长。

## 4. 规模对比

在`qingye_acceptance`中新建独立schema，生成3,000条会话、220,000条消息。其中一条会话追加50,000条文字消息，另一条追加50,000条商品卡片，对应200个不同商品。测试结束删除该测试schema，不向业务库写入规模数据。

同一服务器、相同数据生成规则，预热1次、记录15次；以下单位为毫秒，列出中位数及样本p95。基线为R17查询，优化值来自本轮最终普通全量测试。计时包含同机Go服务/存储调用与数据库处理，不含公网传输和浏览器渲染；不是生产容量承诺。

| 场景 | R17中位数 / p95 | R18中位数 / p95 |
| --- | ---: | ---: |
| 大量未读，会话首页 | 187.753 / 211.173 | 95.388 / 104.480 |
| 大量未读，旧方式跳过2,900条会话 | 407.556 / 476.386 | 65.146 / 79.525 |
| 相同深度，新游标方式 | 无此接口 | 62.985 / 76.681 |
| 含50,000张商品卡片的会话详情 | 99.315 / 125.585 | 38.970 / 40.438 |
| 长会话向前读取50条历史消息 | 0.949 / 1.163 | 1.015 / 1.561 |
| 全部已读，会话首页 | 145.084 / 155.741 | 56.912 / 68.600 |

20个不同会话同时成功发送消息，合计耗时由50.689ms变为39.437ms。本轮没有改变写事务，不能据此宣称写入吞吐有确定提升。消息历史读取也保持原有约1ms水平。

在本样本中，新游标与优化后的旧深分页耗时相近，因为总未读计数仍占主要成本。游标的作用是避免继续随偏移量跳过更多会话，同时改善动态列表翻页边界；本轮主要收益来自分页后再投影、合并重复查询及索引调整。

1. **查询与数据语义审查**：核对权限谓词、LATERAL返回空值、商品ID去重/NULL、同一快照内统计、索引排序和游标参数化；保持原消息写事务。
2. **功能、规模与并发**：后端Linux全量243项通过，0失败/0跳过；HTTP及聊天应用/领域包竞态165项通过，0失败/0跳过；vet、Linux构建通过。用户端123项、管理端65项及两端构建通过。新增测试覆盖123条同时间会话不重不漏、旧offset等价、动态上移、非法/混合游标、另一管理员借用游标、精确未读、重复商品卡片与两种传输的cursor指令。
3. **权限与发布复核**：既有越权、Origin、票据、消息去重、断线重分配测试通过；规模测试后再次通过相关安全用例。部署后双入口各3种匿名会话请求均返回401；检查实际运行进程的可执行文件及散列，不能只核对current链接。

Chrome真实页面验证在独立验收环境完成：50条首页展开至末页；发新消息触发首页刷新后仍可继续加载；末页按钮消失；两端收发、通知、已读与商品咨询上下文正常。验收账户拥有122条历史会话，启用接待后分配到2条会话，界面共124条。页面走WebSocket；WebTransport的游标和收发由真实协议集成测试验证。浏览器记录到扩展消息通道关闭提示，不将其描述为零控制台错误。

未新增依赖，本轮未重新运行依赖漏洞扫描，不沿用旧扫描结果作为新结果。
