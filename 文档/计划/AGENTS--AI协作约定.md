# 项目协作约定

- 当前主线为 React + Go 测试联调版0.7.0-test.1，不得表述为正式生产交付。经营方已授权实现后端、自测后部署152服务器前端5179／后端5180，并上传私有GitHub；5178继续保留前端原型，不覆盖其他服务或8.140生产站。
- PostgreSQL专用库、独立Redis和媒体放152服务器。旧站数据只读提取，保留原价与原分类；用户2026年11月11日确认出售按元、时日租号按元/日、周月租号按元/月，按此规则回填，不覆盖人工报价或换算价格。使用专用测试账户；短信未配置必须明确不可用。原图完整保留，空间不足先停下确认，不自动降质或删除其他数据。
- 管理端独立React项目与部署入口；public/admin后端路由、会话和上传票据隔离。业务验收、并发和安全写测试只在独立qingye_acceptance环境执行。至少三轮代码与缺陷审查，性能工作后再做安全验证；报告真实结果与范围，不承诺绝对无BUG。
- 每个商品详情必须可查看全部有序图片，按需加载、可重试，不设固定图集总量上限。历史原型归档到文档/原型代码，真实项目不得使用原型名称混淆。
- 阅读 README.md、文档/计划/14-development-progress--开发进度.md、文档/开发产出文档/16-test-integration--测试联调说明.md和文档/前期设计文档/09-review-items--需求确认与审阅记录.md，依据最新反馈修改。前后端采用React和Go。
- Redis 和独立对象存储已纳入方案。商品图片不设固定总张数上限；单文件大小和单批处理参数另行管理，不得恢复200张总量限制。
- 首期为商品展示、筛选、详情、客服咨询、会员发布审核、热门推荐及电脑和移动端界面。
- 不自行扩展在线订单、充值、积分支付、提现、结算、自动档期或客服工单系统。
- 功能变化需同步检查业务流程、页面、数据库、接口和验收条目。建议规则与已确认规则分开记录。
- 文档使用简洁、专业的中文。描述操作和结果，避免宣传性措辞及冗余流程。
- 后续获得授权的文档和代码变更统一在此私有仓库提交、推送，完成后报告提交版本与检查结果。
- 不上传真实凭据、会员数据、生产导出和日志；不修改仓库可见性，不进行强制推送或未经授权的生产部署。
- 保留现有用户修改。开发开始后，以项目实际构建和检查规则验证相应改动。

仓库维护细则见 [CONTRIBUTING--仓库维护说明](../CONTRIBUTING--仓库维护说明.md)。
